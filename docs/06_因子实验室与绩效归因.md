# 06 因子实验室与绩效归因 — 产品开发技术方案

## 1. 目标与定位

给现有 11 个因子（回撤、量比、换手、市值、PE、量能趋势、均线、强度、尾盘买点、涨停质量、主力资金）建立内部研究面板：
- 每个因子的 Rank IC / IR / 分层收益 / 衰减曲线；
- 每日推荐的 T+1/T+3/T+5 绩效归因；
- 阈值敏感性与权重优化建议。

优先级：P2。不是直接给票，但对算法公司是长期核心能力。

## 2. 产品方案

### 2.1 页面模块
- 因子统计表：IC 均值、IR、T 值、分层单调性、衰减。
- 推荐绩效归因：赚钱 / 亏钱来自哪个因子。
- 权重优化：在约束权重和 = 1 下给出候选权重组合。

### 2.2 输出口径
- Rank IC = spearman(因子值, 前向收益)。
- IR = mean(IC) / std(IC)。
- 分层收益：按因子值分 5 层，各组平均收益。

## 3. 技术方案

### 3.1 因子值
- 复用 `backend/agents/layer2_signal_engine/skills`，每个 skill 分数作为因子值。
- 新因子按 `BaseSkill` 接口扩展。

### 3.2 统计与优化
- IC/IR/分层用 `pandas` + `scipy`（已依赖）现算。
- 归因：因子暴露 × 因子收益做 Brinson 式归因，进阶用多元回归。
- 优化：`scipy.optimize` 权重网格或贝叶斯优化，约束权重和 = 1。

### 3.3 验证
- 滚动切分，报告样本外表现，防止过拟合。

## 4. 数据存储方案

```sql
CREATE TABLE factor_daily (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  date TEXT NOT NULL,
  code TEXT NOT NULL,
  factor_name TEXT NOT NULL,
  factor_value REAL,
  forward_ret_t1 REAL,
  forward_ret_t3 REAL,
  forward_ret_t5 REAL
);
CREATE INDEX idx_factor ON factor_daily(date, factor_name);
CREATE INDEX idx_factor_code ON factor_daily(code, factor_name);
```

- 本地研究用 Parquet：`data/research/factor_panel.parquet`。
- 页面快照：`reports/factor_stats_latest.json`。

## 5. 数据读取方案

- `GET /api/v1/factor-lab/stats/latest`：读预计算 JSON，秒开。
- `GET /api/v1/factor-lab/detail?factor=volume_ratio`：按需查历史。
- 前端只在研究页面加载明细，Dashboard 不调用重接口。

## 6. 与现有系统集成

- 新增 `backend/plugins/factor_lab/`，读 `stock_scores` / `factor_daily` 与 `screening` 历史。
- 不进入每日邮件主链路，仅研究面板。

## 7. 测试与验收

- 无前视测试：前向收益只使用未来数据、因子值只使用当日及之前数据。
- IC/IR 数值与手算样本一致。
- 验收：任一因子可查看 IC/分层/衰减，且样本外 vs 样本内分别展示。

## 8. 上线与运维

- 盘后本地 / GitHub Actions 重算，Render 只读快照。
- 因子面板版本化，保留历史 metrics。

## 9. 风险与限制

- 因子有效性与市场风格高度相关，需持续监控 IC 衰减。
- 样本量不足时 IC 噪声大，页面需显示样本数与置信提示。
