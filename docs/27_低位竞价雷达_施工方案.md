# 28 低位竞价雷达 — 施工级技术开发方案

> 输入：`docs/27_实时量化交易——集合竞价产品方案.rtf`（产品暂定名「低位竞价雷达」）
> 本文是**施工级**方案：在既有 new-france 代码库之上落地的文件级、接口级、存储级实施计划。
> 复用优先，不重写已存在的 13 集合竞价（`smart_money_radar`）与 16 低位选股（`low_position_scanner`），
> 而是新增一个**编排插件**消费两者的成果，并补齐二者缺失的「低位池驱动的竞价采集、组合评分、推送、复盘」闭环。

## 1. 结论摘要（先看这里）

| 决策点 | 结论 |
|---|---|
| 新插件目录 | `backend/plugins/auction_radar/`（独立目录，可选加载，不改动既有插件） |
| 低位池 | **复用** `low_position_scanner.run_low_position_once` 生成，读 `reports/low_position_latest.json` |
| 竞价采集 | **复用** 13 方案的竞价指标思路与内存帧模型，但**独立实现采集器**（腾讯五档扩展字段 + 东财全市场快照兜底），只对低位池轮询 |
| 评分 | 低位分（复用 `low_score`）× 竞价分（新写 `auction_score`），加权合成 `total_score` |
| 存储 | SQLite 新增 3 张表（集中在 `plugin_models.py`）+ `reports/auction_radar_latest.json` 双写快照 |
| 推送 | 复用邮件 `principal_capital.notifier.send_email` + 新增通用 webhook（企业微信/钉钉/飞书/Telegram） |
| 调度 | 本地常驻 daemon（launchd 保活，模式同 `--run-radar-daemon`），9:15–9:25 轮询、9:25–9:30 推送 |
| 前端 | 可选 P1：新增「低位竞价雷达」页，遵循 `DESIGN.md` 与 `apiFetch` 规范 |

**必须修复的 3 个既有缺陷**（详见 §3）：
1. `smart_money_radar/scheduler.py` 读取 `session["session"]`，而 `trading_session_status` 返回 `market_session`，导致竞价 `pre_open` 分支**永不触发**。
2. `tencent_source.parse_tencent_orderbook` 只解析 33 个字段，缺竞价评分必需的 `vol/amount/turnover/volume_ratio/涨停价/跌停价`，导致 `auction_amount()` 恒为 0。
3. 13 方案竞价采集对象是 `principal_capital` 候选池（≤40 只），**不是**低位池；本产品需要以低位池为采集对象。

## 2. 产品目标与范围

### 2.1 MVP（P0，1–2 周）
- 盘后生成低位候选池（复用 16 插件）。
- 9:15–9:25 对低位池采集集合竞价快照（5s 轮询），计算竞价涨幅/量比/换手/金额/未匹配量/情绪值。
- 低位分 × 竞价分合成总分，输出 Top N。
- 9:25–9:30 邮件 + webhook 推送 Top N。
- 提供 REST 快照接口 + 命令行单轮测试。

### 2.2 V1（P1，1–2 月）
- 多源容错（腾讯 → 东财快照 → TDX）。
- 9:30 后分时监控「下砸再拉升」提醒。
- 盘后复盘：候选当日/次日表现、胜率统计。
- Web 前端页面（低位竞价榜 + 个股竞价时间线）。

### 2.3 V2（P2，3–6 月）
- 模拟盘与绩效统计（可复用 `paper_trading` 插件）。
- 板块情绪/大盘环境过滤（可联动 `emotion_cycle` / `board_rotation`）。
- 移动端 H5/小程序、策略参数自配置。

### 3.4 关键兼容性缺陷（实现前必须先修）

#### 缺陷 1：竞价 pre_open 分支永不触发（阻塞 P0）
`trading_session_status` 返回的是 `market_session`（`router_system.py:60`），但
`smart_money_radar/scheduler.py:22` 写成：
```python
name = session.get("session", "non_trading_day")
```
因此 `name` 恒为 `non_trading_day`，`elif name == "pre_open"` 的竞价分支不会执行。
**修复**：改为 `session.get("market_session", session.get("session", "non_trading_day"))`，
向后兼容两种 key。修复后 13 方案的竞价采集才能实际工作，本产品也依赖此调度。

#### 缺陷 2：腾讯源缺竞价评分字段（阻塞竞价因子）
`tencent_source.parse_tencent_orderbook` 当前只取到 `field[44]`（流通市值），未解析：
- `field[6]` 成交量（手）→ `vol`
- `field[37]` 成交额（万元）→ `amount`
- `field[38]` 换手率（%）→ `turnover`
- `field[49]` 量比 → `volume_ratio`
- `field[47]/[48]` 涨停价/跌停价 → `high_limit/low_limit`
- 五档已解析（`bid_vol1..5/ask_vol1..5`）可算未匹配量
而 `auction.amount()` 依赖 `quote.vol`，缺失导致竞价金额恒 0。
**方案**：为遵循「不改动既有插件」，本插件在 `collector.py` 内**独立实现**扩展解析函数
`parse_tencent_auction_quote(fields)`（字段映射见附录 B），复用 `TencentQuoteSource.fetch_quotes_batch` 的请求逻辑或直接自建 `requests` 会话。**不**修改 `tencent_source.py`，避免影响 07/08/13 已有行为。

#### 缺陷 3：竞价采集对象错误
13 方案采集对象是 `principal_capital` 候选池（`load_watch_pool`，≤40 只）。
本产品的采集对象必须是 **`low_position_scanner` 输出的低位池**。
**方案**：`auction_radar/pool.py::load_low_pool()` 读 `read_snapshot("low_position")`，
字段对齐 `items[].{code,name,low_score,pullback_pct,price_percentile,market_cap,total_amount}`；
若快照缺失/过期，触发 `run_low_position_once()` 兜底生成。

## 4. 总体架构与数据流

```
盘后（T-1 15:10 或 T 日盘前）
  low_position_scanner.run_low_position_once()
        │ 全市场资金流粗筛 → 并发拉K线 → 低位判定 + 涨停历史四级降级
        ▼
  reports/low_position_latest.json  +  low_position_hits 表
        │
T 日 09:15–09:25（本地常驻 daemon）
  auction_radar.collector.poll(low_pool)
        │ 腾讯五档批量(分批) / 东财快照兜底 / TDX 回退
        ▼
  RadarStore.auction_frames[code] = [frame...]  （内存滑动窗口）
        │
  factors.py 计算竞价因子 → scoring.py 合成 total_score → risk.py 风险标记
        ▼
  09:25–09:30
  Top N 物化 reports/auction_radar_latest.json（双写）
  落库 auction_candidates 表
  邮件 + webhook 推送
        ▼
  09:30 后（P1）分时监控 + 盘后复盘 auction_daily_perf
```

**设计原则**（对齐项目规范）：
- 外部 HTTP 全部带 `timeout`；独立请求 `asyncio.gather` + `Semaphore` 限流。
- 时间一律 `BEIJING_TZ`，禁止裸 `datetime.now()`。
- 插件独立目录、`register_router()` 可选加载、失败只记日志不阻断主链路。
- 快照为主读路径（秒开），SQLite 供历史/明细，符合 14 插件既有约定。

## 5. 数据源方案

### 5.1 竞价实时源（9:15–9:25）

| 源 | 优先级 | 能力 | 限制 | 实现位置 |
|---|---|---|---|---|
| 腾讯 `qt.gtimg.cn` | 主 | 五档 + 现价 + 昨收 + 量/额/换手/量比（需扩展解析） | 单批 URL 长度有限，建议每批 ≤ 60 只 | `collector.TencentAuctionSource` |
| 东方财富 `push2 clist/get` | 兜底 | 全市场分页，含 `f2/f3/f5/f6/f8/f10/f21` | 五档字段需单独 `ulist` 或缺失，未匹配量降级 | `collector.EastmoneyAuctionSource` |
| pytdx TCP | 回退 | 五档虚拟开盘/匹配量（13 方案主源） | 免费服务器不稳定、需本地国内 IP | 复用 `smart_money_radar.sources.tdx_source.TdxPool` |

**关键结论**：竞价期间（9:15–9:25）AkShare/Tushare 不返回可靠快照，**不能**作为竞价实时源，只用于盘后历史。

### 5.2 低位池源（盘后）
- 复用 `fetch_market_fund_flow_resilient`（东财→akshare 同源兜底→新浪独立源，含熔断/缓存降级）。
- 复用 `historical_kline.fetch_historical`（东财 push2his 前复权 → 腾讯 qfq），130 日窗口。
- 涨停历史四级降级已在 16 插件实现（db → tushare → akshare → unavailable），无需重写。

### 5.3 采集规模与限流
低位池通常在 **100–400 只**（主板、市值 20–300 亿、成交额>5000 万、低位 AND-OR）。
- 腾讯批量：每批 60 只，400 只 = 7 批，5s 轮询 → 约 84 次请求/分钟，可控。
- 若低位池 > 600 只：按 `low_score` 截断 Top 600（竞价扫描预算），或降频到 8–10s。
- 批次间 `asyncio.gather` 并发 ≤ 4，单批 `timeout=(3,5)`，失败批记录 error 不阻断整轮。

```python
class AuctionFrame(Base):
    """28 低位竞价雷达：单只候选竞价采样帧（9:15–9:25 每 5s 一帧）。"""
    __tablename__ = "auction_frames"
    id = Column(Integer, primary_key=True, autoincrement=True)
    date = Column(String(10), nullable=False)          # YYYY-MM-DD
    ts = Column(String(19), nullable=False)            # YYYY-MM-DDTHH:MM:SS
    code = Column(String(6), nullable=False)
    name = Column(String(50))
    price = Column(Float)                               # 虚拟开盘价
    last_close = Column(Float)
    gap_pct = Column(Float)                             # 竞价涨幅%
    vol = Column(Float)                                 # 匹配量(手)
    amount = Column(Float)                              # 匹配金额(元)
    turnover = Column(Float)                            # 换手率%
    volume_ratio = Column(Float)                        # 量比
    bid_vol_total = Column(Float)                       # 买一~买五未匹配量
    ask_vol_total = Column(Float)                       # 卖一~卖五未匹配量
    source = Column(String(30))
    __table_args__ = (Index("idx_af_date_code_ts", "date", "code", "ts"),)


class AuctionCandidate(Base):
    """28 低位竞价雷达：当日最终候选与评分（9:25 物化）。"""
    __tablename__ = "auction_candidates"
    id = Column(Integer, primary_key=True, autoincrement=True)
    date = Column(String(10), nullable=False)
    code = Column(String(6), nullable=False)
    name = Column(String(50))

    auction_score = Column(Float)                       # 竞价分(新)
    total_score = Column(Float)                         # 合成总分
    rank = Column(Integer)
    gap_pct = Column(Float)
    vol_ratio = Column(Float)
    turnover = Column(Float)
    amount = Column(Float)
    emotion_value = Column(Float)                       # 竞价换手×竞价量比
    bid_unmatched = Column(Float)
    ask_unmatched = Column(Float)
    events_json = Column(Text)                          # ["诱多撤单","持续承接"]
    risk_flags_json = Column(Text)                      # ["高开透支","炸板降权"]

    pushed_at = Column(String(30))

class AuctionPerf(Base):
    """28 低位竞价雷达：盘后复盘（无前视回填）。"""
    __tablename__ = "auction_perf"

    signal_date = Column(String(10), nullable=False)

    name = Column(String(50))
```

### 6.3 帧落库策略（避免高频 SQLite 锁）
- 竞价期（9:15–9:25）帧**只进内存** `AuctionStore.auction_frames`（`deque(maxlen=240)`）。
- 9:25 锁定后，一次性 `db_append("auction_frames", ...)` 写入 Top N 的全帧序列（供个股时间线）；
- 非 Top N 候选只写最终 `auction_candidates` 一行，不写帧（控制写量）。
- 复盘 `auction_perf` 盘后 `run_auction_radar_review` 批量回填。

### 7.1 关键函数签名（施工契约）


## 8. 核心策略实现

### 8.1 低位判定（复用，不重写）
- 直接消费 `low_position_scanner` 的 `low_score` 与 `is_low_position`（AND-OR：60 日回撤≥25% 且 [120 日百分位≤30% 或 MA20 下]）。
- 竞价雷达**不重复拉 K 线**；低位分从 `low_position_latest.json` 的 `items[].low_score` 读取。
- 若低位池为空，竞价雷达本轮 `status=empty_pool`，不推送（符合「无数据不造假」）。

### 8.2 竞价因子（新写 factors.py，全除零防护）

| 因子 | 口径 | 归一化到 0–100（用于 auction_score） |
|---|---|---|
| 竞价涨幅 | `(price-last_close)/last_close*100` | 3%–7% 满分；0–3% 线性；>9% 扣分；负值低分 |
| 竞价量比 | `vol / hist_avg_vol`（历史同日同时段均量，盘前用近 20 日 9:25 量均值估算，缺失时降级为近 20 日日均量/240 分钟） | 2.5–8 满分 |
| 竞价换手 | `vol*100 / float_shares`（`float_shares = float_mcap/price`，或腾讯流通市值推算） | 1%–3% 满分 |
| 竞价金额 | `price*vol*100` | >1000 万满分，500 万以下低分 |
| 未匹配量 | `bid_vol_total - ask_vol_total` 及其斜率（连续 3 帧买盘未匹配量递增） | 正向净买盘 + 斜率>0 加分 |
| 情绪值 | `turnover(%) * volume_ratio` | ≥10 强；5–10 中；<5 弱 |

```python
# 默认竞价权重（env 可覆盖，附录 A）
AUCTION_WEIGHTS = {"gap": 0.25, "vol_ratio": 0.30, "turnover": 0.15,
                   "amount": 0.15, "unmatched": 0.15}
```

### 8.3 组合评分（产品公式落地）
产品公式：`score = w1*低位分 + w2*竞价量比分 + w3*高开分 + w4*资金分 + w5*板块分`
映射为两级：
```python
total_score = round(
    W_LOW      * (low_score / 100) +       # 低位分(复用, 0-100)
    W_AUCTION  * (auction_score / 100) +   # 竞价分(因子合成, 0-100)
    W_RISK     * (risk_score / 100),       # 风险分(诱多/透支/炸板降权后)
    4) * 100
# 默认权重 W_LOW=0.35, W_AUCTION=0.50, W_RISK=0.15
```
> 产品方案中的「高开分/资金分/板块分」在 MVP 阶段合并进 `auction_score`（竞价涨幅=高开、竞价金额+未匹配=资金）；「板块分」P2 接入 `board_rotation`。

### 8.4 风险过滤（risk.py）
1. **高开透支**：`gap_pct > 9 且 vol_ratio < 2` → 剔除（`flag_high_open_exhaustion`）。
2. **虚假涨停撤单（诱多）**：9:15–9:20 买盘挂单高、9:20 后挂单骤减且价格下移 → `events=["疑似诱多撤单"]`，`risk_score` 打 0（复用 13 的 `withdraw_lure` 逻辑，注意用 `bid_vol_total+ask_vol_total` 序列）。
3. **昨日炸板/连板高位**：读 `limit_up_daily` 昨日 `break_count>0` 或 `board_height≥3` → 权重降 30%（`penalty_zt_break`）。
4. **竞价涨幅>9% 且情绪值<5**：高开无量 → 降权不剔除（保守，避免误杀）。

### 8.5 昨日涨停竞价强度（可选联动）
复用 13 的 `prev_zt_auction_strength`，作为大盘情绪背景值输出到快照 `prev_zt_auction`，不作为单票评分硬项。

## 16. 风险与合规

1. **免费竞价源不稳定**：腾讯/东财竞价期可能限流或延迟；必须多源 + 熔断 + 降频，最坏情况 9:24 才取到末帧仍可推送。
2. **免费源无逐笔/完整未匹配队列**：五档未匹配量是近似，诱多判定为启发式（同 13 限制），推送文案注明「近似信号」。
3. **过拟合**：竞价因子阈值（3–7%、2.5–8、1–3%）需通过复盘回测校准，避免拍脑袋。
4. **实盘风险**：高开低走、炸板、量化干扰；工具只提醒不自动交易。
5. **合规**：不提供投资建议、不代客理财、不承诺收益；快照/邮件统一加 `disclaimer`。
6. **数据版权**：免费接口仅限个人自用，不商用。
