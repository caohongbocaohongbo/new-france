# 07 盘口委托失衡与五档动态雷达 — 产品开发技术方案

## 1. 目标与定位

对标 Level-2“盘口异动 / 委比委差”，基于现有 pytdx 五档盘口做类 L2 动态雷达：
- 委比委差、买五档 / 卖五档总额；
- 盘口失衡、托单 / 压单识别；
- 卖一挂单量骤减但价格不跌（疑似撤压）、买一挂单量骤增（疑似垫单抢筹）。

优先级：P0。本地雷达已具备滑动窗口与基础指标，改动小。

## 2. 产品方案

### 2.1 页面模块
- 盘口异动榜：观察池内按盘口失衡 / 突变强度排序。
- 个股盘口时间线：五档总额、买卖盘强弱、委比变化。
- 事件提示：疑似撤压 / 垫单抢筹 / 大单托盘。

### 2.2 输出口径
- `bid_amt = Σ bid_i × bid_vol_i`，`ask_amt = Σ ask_i × ask_vol_i`。
- 盘口失衡 = (bid_amt - ask_amt) / (bid_amt + ask_amt)。
- 档位集中度 = max(vol_i) / Σ vol_i。
- 卖压衰减 = 卖一量最近 K 帧斜率（负 = 撤压 / 消化）。
- 买盘堆积 = 买一量最近 K 帧斜率（正 = 垫单）。

## 3. 技术方案

### 3.1 数据源
- `backend/plugins/smart_money_radar/sources/tdx_source.py::TdxPool.fetch_stock` 的五档字段。
- 复用 `RadarStore.quotes` 滑动窗口，不新增采集端。

### 3.2 算法
- 在 `smart_money_radar/indicators.py` 新增纯函数：
  - `bid_ask_imbalance(quote)`；
  - `top_concentration(quote)`；
  - `ask_pressure_decay(series)`；
  - `bid_buildup(series)`。
- 事件判定（阈值进 config）：
  - 卖一量 60s 下降 > 40% 且价格未跌 → 疑似撤压；
  - 买一量 60s 上升 > 50% → 疑似抢筹垫单。

### 3.3 覆盖与调度
- 本地观察池 40 只，`poll_interval_s=4` 默认 4 秒轮询。
- 全市场覆盖靠 09 方案的大单分层资金流，不靠五档逐票轮询。

## 4. 数据存储方案

- 五档原始帧只存本地内存滑动窗口，不落盘（`RadarStore` 已实现）。
- 触发事件写 `data/orderbook_events_{date}.json`。
- 聚合结果写 `reports/orderbook_latest.json`。

## 5. 数据读取方案

- `GET /api/v1/smart-money-radar/orderbook/latest`：读 JSON。
- `GET /api/v1/smart-money-radar/orderbook/{code}`：本地读内存窗口返回最近 N 帧。
- 页面实时刷新走轮询，前端已有 `apiFetch` 模式。

## 6. 与现有系统集成

- 在 `backend/plugins/smart_money_radar/` 内扩展 `indicators.py / service.py / router.py`，不新开插件。
- 触发事件可并入雷达邮件（《本地雷达》 tag）。

## 7. 测试与验收

- 指标边界：全买盘 = 100，全卖盘 = 0，挂单量为 0 防除零。
- 事件判定：卖一量递减且价格不跌触发撤压，卖一量递增触发垫单。
- 验收：盘口事件可解释、无重复刷屏（复用冷却去重）。

## 8. 上线与运维

- 本地常驻 `--run-radar-daemon`，launchd 保活。
- 指标阈值用环境变量 `RADAR_*` 覆盖。

## 9. 风险与限制

- 只有五档，无法看到十档 / 千档与委托队列；撤压 / 垫单是启发式近似。
- 免费 pytdx 盘中可能限频，需保持 `fetch_concurrency=1`。

## 10. 里程碑

1. M1：盘口指标纯函数 + 单测。
2. M2：滑动窗口事件判定。
3. M3：页面 + 邮件提示。
