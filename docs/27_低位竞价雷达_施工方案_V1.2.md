## 1. 修订结论与施工红线

### 1.1 保留、调整、禁止

| 类别 | 决策 |
|---|---|
| 保留 | 复用插件 16 低位池、插件 13 竞价纯函数思路；插件 28 独立编排 |
| 保留 | Python 常驻 daemon、内存滑窗、SQLite、JSON 快照、REST |
| 保留 | `PRELIMINARY / CONFIRMED / UNCONFIRMED` 状态机与「09:24 预测不冒充 09:25 成交」 |
| 保留 | `AuctionQuote` 字段级契约、`indicative_* / final_*` 分离、源时间≠接收时间 |
| 保留 | 缺失因子重归一化 + `factor_coverage` 门槛；非 TopN 也落摘要（防幸存者偏差） |
| 调整 | 字段契约按**可得性双分支**组织（§4.1） |
| 调整 | 采集对象加入**盘前竞价强势清单**（§5.2） |
| 调整 | 诱多语义改为**挂单压力衰减**（§6.5） |
| 调整 | Outbox 裁剪为单进程版（§7.2 / §9.2） |
| 禁止 | 仅凭 HTTP 200 判定行情新鲜；未验证字段强行填 0 |
| 禁止 | 宣称「撤单」「机构建仓」等无申报级/逐笔证据的断言 |
| 禁止 | 查询接口触发低位池重算或第三方请求；9:25 关键路径做批量帧落库 |
| 禁止 | 自动下单、承诺收益、用测试数据冒充正式行情 |

### 1.2 字段可得性双分支（V1.2 最高优先级决策）

免费公开接口（腾讯 `qt.gtimg.cn`、东财 `push2`）在 9:15–9:25 **是否稳定提供「虚拟匹配量 / 虚拟未匹配量」是未知的**，且大概率**不提供**（这两个字段是 Level-2 竞价揭示/交易所授权口径，而产品方案明确用户无 Level-2）。因此 V1.2 不再把这两个字段当默认前提：

```text
Phase 1 交易日采样（见 §4.1 数据源验证表）
  ├─ 实测确认某源稳定给出「虚拟匹配量 + 虚拟未匹配量」
  │     → 分支 A：完整因子（gap/金额/换手/相对量比/未匹配量/情绪值）
  └─ 无法确认（默认预期）
        → 分支 B：有限因子 limited_v1
             只用「虚拟参考价 + 昨收 + 五档挂单量 + 涨停/跌停价 + 低位分」
```

- **P0 默认按分支 B 设计、开发、验收**；分支 A 是「实测意外可用」时的升级路径，不阻塞 P0。
- 分支 B 下，竞价金额/换手/量比**只有在源字段语义被实测确认后才加入有效权重集**；否则从权重集移除，不得填 0。
- 评分版本号明确：分支 B = `auction_v1_limited`，分支 A = `auction_v1_full`（见 §6）。

### 1.3 上线 Gate 分级

**Gate-P0（任一失败不得发布「已确认竞价榜单」）：**
1. **G1 数据源核验**：至少两个完整交易日采样；确认腾讯主源字段索引、单位、时间语义、竞价期是否更新。未确认字段不参与正式评分。
2. **G2 最终撮合核验**：取得 9:25 后真实可验证的开盘价/量；不能确认时标 `UNCONFIRMED`，不输出 `CONFIRMED`。

**上线前复核清单（不阻塞 P0 开发，真盘发布前检查）：**
- G3 全链路状态机：进程重启、源超时、写库失败可恢复；同日同版本只有一份逻辑最终信号。
- G4 推送可靠性：Outbox 落库、各通道独立状态、幂等键、失败重试、操作日志。
- G5 可观测性能：源时间/接收/评分/发布/Webhook/SMTP 各时间点及 P50/P95/P99。

### 1.4 P0 与 P1 边界

- **P0 必做**：数据字段验证（主源腾讯）、时间语义、盘前准备/冻结、5 秒全池采集（单飞防重叠）、增量评分、`UNCONFIRMED` 兜底、快照原子发布、单进程 Outbox 推送、只读 REST、G1/G2 验收。
- **P1 再做**：1–2 秒热点池、竞价时间线前端/帧落库、跨进程 SSE、9:30 后分时提醒、历史竞价量比自学习、复盘/模拟盘、Outbox 租约与多 worker。
- **明确不做**：重构 13/16 插件、全市场逐笔重建、自动交易、Kafka/Redis/K8s、三源齐验。

## 2. 事实核验结论（已读代码，非"待核验"）

### 2.1 三个既有缺陷 —— 已确认存在

1. **竞价 pre_open 分支不触发（确认）**：`backend/plugins/smart_money_radar/scheduler.py:22` 读 `session.get("session", "non_trading_day")`，而上游 `backend/api/router_system.py::trading_session_status` 返回的是 `market_session`（约 60 行）。故 `name` 恒为 `non_trading_day`，竞价分支不执行。**施工直接修复**：兼容读取 `session.get("market_session", session.get("session", "non_trading_day"))`，并补回归测试。
2. **腾讯源缺竞价字段（确认）**：`backend/plugins/smart_money_radar/sources/tencent_source.py::parse_tencent_orderbook` 只解析到 `field[44]`，缺 `vol(6)/amount(37)/turnover(38)/volume_ratio(49)/high_limit(47)/low_limit(48)`。**本插件在 `collector.py` 独立扩展解析，不改 13 插件**。
3. **竞价采集对象错误（确认）**：13 插件 `service.py::load_watch_pool` 消费 `principal_capital` 候选池（≤40 只），非低位池。**新插件显式绑定 16 号低位池**，不改 13 业务。

> 以上三项是「代码结构事实」，可直接修；但**字段语义**（腾讯 field[6]/[37]/[38]/[49] 在竞价期到底代表什么）仍是实盘验证项，见 §4.1。

## 3. 成功标准与数据时序（北京时间）

| 阶段 | 时刻 | 必须完成 | 失败处理 |
|---|---|---|---|
| T-1 盘后 | 15:10 后 | 复用 16 生成低位池，记录 `asof_trading_day`、口径、数据源 | 告警；产物保留但不得冒充当日 |
| T 盘前 | 09:10 | 加载上一**有效交易日**池；装载流通股本/历史基准/风险标签；源健康检查 | `PREPARE_FAILED`，仅在准备窗重试 |
| T 盘前 | 09:14:30 | 池冻结，`pool_hash` 固定 | 无池 → `SKIPPED_NO_POOL`；池陈旧 → `DEGRADED_STALE_POOL`（可用+标注 asof） |
| 竞价阶段 1 | 09:15–09:20 | 全池轮询、预判、记录源数据 | 降级但标质量 |
| 竞价阶段 2 | 09:20–09:25 | 持续轮询、增量评估、近末端优先 | 源失效 → `DEGRADED` |
| 预测榜单 | 09:24:45–09:24:59 | 最新有效帧形成 `PRELIMINARY`；不得标注最终开盘价 | 只读展示，不发「最终确认」通知 |
| 撮合确认 | 09:25:00 后 | 预算窗口内获取并验证最终开盘价/量 | 超时 → `UNCONFIRMED`，只发故障/未确认提示 |
| 发布 | 取得确认后 | 增量更新、硬过滤、冻结版本号、提交持久化信号、原子发布快照 | 崩溃可恢复 |
| 通知 | 快照可查后 | 邮件/Webhook 独立异步提交 | 失败重试，不阻塞榜单 |
| 盘后 | 15:10 后 | 复盘（P1），回填表现与策略版本 | 缺数据不补造 |

**状态机**（每交易日/策略版本唯一）：

```text
INIT → PREWARMING → POOL_FROZEN → POLLING
                               ├─> PRELIMINARY → WAITING_FINAL
                               │       ├─> CONFIRMED → PUBLISHING → PUBLISHED
                               │       ├─> UNCONFIRMED（超时/无最终证据）
                               │       └─> FAILED（数据严重不一致）
                               └─> DEGRADED / SKIPPED_NO_POOL / DEGRADED_STALE_POOL
PUBLISHED → NOTIFYING → NOTIFIED / PARTIALLY_NOTIFIED / NOTIFY_FAILED
```

- `CONFIRMED` 指「发布所需最终字段具有足够证据」，支持字段级证据 `confirmed_fields=["open_price"]`；总体信号可为 `PARTIAL`/字段级确认。
- 不得以 `datetime.now() >= 09:25` 把旧帧直接升级为 `CONFIRMED`。

## 4. 数据采集契约：先准确，后快

### 4.1 统一数据结构（双分支，独立于供应商）

```python
class AuctionQuote:
    trade_date: str
    code: str
    name: str | None
    source: str                       # tencent | eastmoney | tdx
    source_timestamp: str | None      # 无源时间必须为 None，不造时间
    received_at: str                  # 北京时间带 +08:00
    market_phase: str                 # PRE_AUCTION | NON_CANCEL | FINAL | UNKNOWN
    indicative_price_yuan: float | None      # 虚拟参考价（分支 A/B 均需）
    prev_close_yuan: float | None
    float_shares: int | None
    price_limit_up_yuan: float | None
    price_limit_down_yuan: float | None
    # 分支 A：完整因子（仅实测确认可得时启用）
    indicative_match_shares: int | None
    indicative_unmatched_shares: int | None
    unmatched_side: str | None        # BUY|SELL|UNKNOWN
    final_open_price_yuan: float | None
    final_match_shares: int | None
    # 分支 B：有限因子（P0 默认，免费源可稳定提供）
    orderbook_bid_vol_total: float | None    # 五档买挂单量（近似，非未匹配量）
    orderbook_ask_vol_total: float | None
    # 审计字段（保留原始值，不默认是竞价匹配量）
    source_volume_raw: float | None
    source_amount_raw: float | None
    source_volume_unit: str | None    # lot | share | unknown
    raw_payload_hash: str
    quality: str                      # VALID | PARTIAL | STALE | INVALID
    quality_reasons: list[str]
    confirmed_fields: list[str]
```

**字段原则**：
- `indicative_*` 用于 9:15–9:25 预测；`final_*` 只能由最终撮合口径证据赋值。
- `orderbook_bid_vol_total` 是**五档挂单量的近似**，绝不写成 `unmatched_shares`（未匹配量）；二者不得混用。
- 供应商原始值、单位、报文哈希保留用于审计；日志脱敏令牌。
- 源无法提供某字段 → 该因子从有效权重集移除，不以 0 伪造。
- `received_at` 不得写成 `source_timestamp`；无法度量真实传输延迟时标 `source_lag_unknown`。

### 4.2 数据源验证表（P0 只阻塞腾讯主源）

| 来源 | 验证要求 | 正式可用条件 |
|---|---|---|
| 腾讯 `qt.gtimg.cn`（**P0 主源，阻塞**） | 9:15/9:19:5x/9:20/9:24:5x/9:25+ 样本；GBK、字段位置、单位、字段更新时间；五档是否更新 | 被实测验证的字段才进模型；五档不能自动当未匹配量 |
| 东财 `push2`（**P1 兜底，登记不阻塞**） | 顺手采样；`f2/f3/f5/f6/f8/f10` 竞价期语义 | 仅补已验字段；不同口径不混算 |
| TDX（**P1 回退，登记不阻塞**） | 盘前虚拟价/量返回、服务器时间、断连 | 字段实测通过后作替代源 |

**执行**：新增 `auction_radar/probe.py`（只读采样），输出 csv/jsonl，覆盖沪/深、主板、不同涨跌停情形，至少两个完整交易日。能力不足时先发布「有限因子竞价雷达」，公开缺失因子并降置信度，不允许用未验证数据填充。

### 4.3 数据质量门禁 `QuoteQualityGuard`

```python
validate_quote(quote, trade_day, phase, previous_quote) -> QualityResult
# result: quality, reasons, allowed_fields, lag_ms|None, fallback_required
```

规则：交易日/代码匹配；时间戳不倒退；正价格、单位可解释；对应板块价格限制合理；关键字段来源一致；疑似旧行情/跨源口径冲突降级。价格限制按板块、ST 状态、是否无涨跌幅限制阶段判断，**不用统一 `gap>9%` 代替所有股票**。跨源切换保留每只股票 `source` 与 `quality`；回退源缺字段时对该票取消对应因子并标 `PARTIAL`，不拿主源旧值冒充新值。

### 5.1 读池 / 重算 / 冻结分离

```python
    """仅在盘前/盘后后台作业执行；必要时触发 16 号插件。"""

async def freeze_pool(trade_day: date) -> FrozenPool:
    """锁定 code 列表/low_score/历史基准/风险标签/池来源版本/池哈希。"""
```

- 盘前读**上一有效交易日**盘后池；节假日用 `prev_trading_day` 判定，不把 T-1 误判为过期。
- **池陈旧降级**：有快照但 `asof_trading_day < prev_trading_day(trade_day)` → `DEGRADED_STALE_POOL`，**可用但标注 asof 日期、降置信度**；完全无快照 → `SKIPPED_NO_POOL`。
- 9:14:30 后不改池成员；强制手动更新仅限受控 CLI、生成新版本、默认关闭。
- 09:15 后所有 GET 不触发第三方 HTTP / 低位重算。

### 5.2 采集对象 = 低位池 ∪ 盘前竞价强势清单（V1.2 新增）

仅扫低位池会系统性漏掉「竞价先强势启动、形态却非标准低位」的票。P0 采用并集，避免回到全市场 5 秒轮询：

```text
采集对象 = frozen_low_pool ∪ auction_hot_candidates
auction_hot_candidates = 盘前(≤09:10)拉取一次的东财涨停/高开异动清单
                         （复用 fetch_market_fund_flow_resilient 或东财 clist 按 f3 涨幅排序取前 N）
```

- 去重、统一 `code`、复用 `market_filter` 市场过滤。
- 总量仍受 `RADAR_AUCTION_POOL_MAX` 约束（默认 600）。
- `auction_hot_candidates` 同样在 9:14:30 冻结，与低位池合并后生成统一 `pool_hash`。

### 5.3 P0 稳定采集：全池 5 秒，防重叠优先

- `batch_size<=60`、并发≤4 为初值，按实测响应尺寸/429/超时调优。
- **single-flight**：上一轮未结束，下一轮不并发重叠；记录 `skipped_poll_rounds`。
- `poll_deadline`：每轮总预算、批次超时、取消策略；旧响应不覆盖新帧。
- 分离 `fetch / normalize / validate / score`，异常不阻断全池；失败批独立处理。

### 5.4 09:25 最终确认

```python
async def finalize_once(trade_day, strategy_version):
    run = await claim_run_once(trade_day, strategy_version)  # DB 唯一键
    if not run.claimed:
        return await read_published_result()
    preliminary = store.get_latest_valid_ranking()
    deadline = monotonic() + cfg.final_wait_max_s
    while monotonic() < deadline:
        final_quotes = await collector.fetch_final_candidates_and_boundary()
        quality = verify_final_quotes(final_quotes, preliminary)
        if quality.minimum_publishable:
            return await publish_final_result_atomically(quality, run)
        await asyncio.sleep(cfg.final_retry_interval_s)
    await mark_unconfirmed_and_alert(run, reason="final_market_data_not_verified")
```

- `final_wait_max_s` 初值 **15 秒**，不意味着 9:25:15 必拿到数据。
- `min_confirmed_count / required_fields` 门槛；达不到停发正式榜单，发「未确认」故障通知。
- 已发布不可被旧源覆盖；修正需 `revision=2` + 独立通知，不静默篡改。

## 6. 竞价因子、评分和风险口径

### 6.1 单位规则

内部标准单位：人民币元、股、百分比数值（2.5 代表 2.5%）。「手」按每手 100 股转换。

```python
match_amount_yuan = indicative_price_yuan * indicative_match_shares      # 仅分支 A 且字段有效
auction_turnover_pct = indicative_match_shares / float_shares * 100      # 仅分支 A
orderbook_pressure = bid_vol_total - ask_vol_total                       # 分支 B 近似，非未匹配量
```

### 6.2 双分支因子集（核心）

| 因子 | 分支 A（完整） | 分支 B（有限，P0 默认） |
|---|---|---|
| 竞价涨幅 `gap` | ✓（虚拟参考价 vs 昨收） | ✓ |
| 盘口压力 `orderbook_pressure` | ✓（可另算未匹配量） | ✓（五档挂单量近似） |
| 竞价涨停封单 `limit_up_seal` | ✓ | ✓ |
| 低位分 `low_score` | ✓（复用 16） | ✓（复用 16） |
| 竞价金额 `amount` | ✓ | 仅源字段语义实测正确才启用 |
| 竞价换手 `turnover` | ✓ | 同上 |
| 竞价相对量比 | ✓（历史 9:25 基准） | 同上；P0 无历史基准 → `null` |
| 未匹配量/情绪值 | ✓ | ✗（免费源大概率无） |

### 6.3 评分（缺失重归一化）

```python
def weighted_auction_score(values, weights, *, min_coverage=0.70):
    valid = {k: v for k, v in values.items() if v is not None and k in weights}
    coverage = sum(weights[k] for k in valid) / sum(weights.values())
    if coverage < min_coverage:
        return None, coverage
    score = sum(valid[k] * weights[k] for k in valid) / sum(weights[k] for k in valid)
    return round(max(0, min(100, score)), 2), coverage
```

合成（权重为示例，需配置+复盘校准；`risk` 不再作为凭空加分的独立项）：

```python
base_score = W_LOW * low_score + W_AUCTION * auction_score   # 分支B默认 0.40/0.60
total_score = clamp(base_score - risk_penalty, 0, 100)
```

- 硬风险失败直接排除正式榜单（保留审计原因）；软风险 `risk_penalty` 0–100 扣分并存证。
- 同分按数据质量、次级指标、代码确定性排序；不以缺失字段填 0 制造随机波动。
- `strategy_version`：分支 B = `auction_v1_limited`；分支 A = `auction_v1_full`。

### 6.4 竞价涨停封单强度（V1.2 新增）

```python
def limit_up_seal_strength(price, limit_up, bid_vol1, bid_vol_series) -> float | None:
    """竞价一字涨停（price≈limit_up）时，用买一挂单量及其增速评估封单强度。
    五档买一挂单量是「挂单近似」，不是权威涨停未匹配量。"""
    if limit_up is None or price is None or price < limit_up * 0.999:
        return None
    # 封单量规模 + 挂单量增速 合成 0-100；仅描述盘口强弱，不推断主力意图
```

- 高封单强度 → 打板强势加分；封单强度骤降 + 价格下移 → 转入「挂单压力衰减」风险（§6.5）。

### 6.5 挂单压力衰减（V1.2 替换「诱多撤单」）

```python
def orderbook_pressure_decay(frames, drop_pct=0.5) -> bool:
    """近 K 帧五档买挂单量显著下降(>=drop_pct)且虚拟参考价下移。
    只描述「买盘挂单压力衰减 + 价格走弱」的可观测现象，不宣称撤单。"""
```

- **两个阶段都不宣称「撤单」**：9:15–9:20（可撤段）挂单量下降可能是撤单、被动成交或价格跳变；9:20–9:25（不可撤段）挂单变化来自新申报与价格变动导致的重新撮合。除非有申报级逐笔，否则只标 `events=["挂单压力衰减"]`。
- 该信号作为**软风险扣分** + 事件标注，不作为唯一硬过滤依据。

### 6.6 信号结果语义

每只股票输出：`low_score / auction_score / total_score / factor_coverage / quality / confirmed_fields / events / risk_flags / excluded_reason / strategy_version`。只展示可追溯的预测/最终价格与量；不得文案表述「机构买入」「主力建仓」等无可验证依据的结论。

## 9. 推送链路：快实时且可恢复

### 9.1 消息类型与时机

| 类别 | 触发 | 原则 |
|---|---|---|
| 正式竞价榜单 | 确认完成且快照已发布 | `【低位竞价雷达】09:25 最终确认 Top N`；含数据时间/质量/免责 |
| 未确认告警 | 等待最终行情到期 | `【竞价数据未确认】今日不发送正式榜单`；列原因 |
| 采集故障 | 连续异常达阈值 | `【竞价雷达故障】`；不伪造标的 |
| 更正版本 | 已发正式榜单后有受验证更正 | 显示 revision/差异 |

### 9.2 单进程 Outbox Worker（V1.2 裁剪版）

- 逻辑事件按 `(trade_date,phase,strategy_version,revision)` 生成稳定 `event_key`；每通道/收件人独立记录。
- 状态：`WAITING_PUBLISH→READY→SENDING→ACCEPTED`；失败 `RETRY_WAIT→READY` 或 `FAILED_FINAL`。
- **单进程顺序消费**；指数退避+抖动，`RETRY_MAX` 默认 2。
- `ACCEPTED` 表示远端服务**受理请求**，非投递到设备。
- 本地唯一键防本地重复入队；远端「恰好一次」不保证，尽可能用平台业务消息 ID。
- 4 个 Webhook + 邮件**各自独立执行**，不互相拖慢。

### 9.3 邮件

- `send_email` 是同步 `smtplib` → 必须在 `asyncio.to_thread`/独立线程，禁止阻塞事件循环。
- 09:10 做 DNS/端口/认证健康检查（不误发测试消息）；TLS/认证保持。
- HTML 盘前预编译，9:25 只填数；展示 `asof`、确认状态、来源、因子覆盖度、风险说明。
- 区分 `SMTP_ACCEPTED` 与 `INBOX_DELIVERED`（后者需独立探针，不由发送函数推断）。

### 9.4 Webhook

- 平台标准鉴权/签名；地址/Token 仅环境变量，日志脱敏。
- 异步 HTTP 客户端复用连接；每通道独立超时/错误分类/可重试分类。
- HTTP 200 但业务 JSON 错误码非成功 → 判失败。
- 即时消息只放 TopN 摘要 + 完整报告链接/快照版本；邮件承载完整表格。

## 14. 开发完成判定（Definition of Done）
