# 15 四维共振信号 — 产品开发技术方案

## 1. 目标与定位

将现有已采集的资金流、技术形态、板块强度三类数据融合成一个统一的"四维共振分"，在成交量区域用红绿灯标注主力进出时机。回答一个问题：**现在这只票四个维度是否共振，主力是在买还是在卖？**

优先级：**P1**。D1/D2/D4 数据已现成，D3 依赖 05 板块轮动方案（旁路降级可绕过）。

与现有功能的区别：
- `principal_capital` 只看资金流单维度；
- `smart_money_radar` 只覆盖观察池 40 只；
- 本方案用四维加权融合全市场覆盖，输出可解释的红绿灯榜单。

## 2. 产品方案

### 2.1 用户场景
盘后自动产出次日四维共振榜，次日 09:25 开盘前可查。用户看红绿灯榜决定哪些票值得重点跟踪，红灯票喂给本地雷达做盘中精细确认。

### 2.2 页面模块
- 共振榜：全主板按共振分排序，信号灯（🔴/🟡/🟢）标注，可按信号过滤。
- 四维雷达图：个股页展示 D1/D2/D3/D4 各维度得分六边形。
- 统计卡片：当日红灯/黄灯/绿灯各几只，与历史均值对比（异常多说明阈值需校准）。

### 2.3 四个维度定义（基于真实可得数据）

| 维度 | 数据来源 | 核心指标 | 权重（D3在线）| 权重（D3降级）|
|------|---------|---------|------|------|
| D1 资金主力 | `tier_flow` 的 `smart_ratio + state` + 时间序列持续性 | 大单净买占比 + 状态 + 吸筹持续轮次 | 35% | 45% |
| D2 价格动量 | `historical_kline` 日线 | 5日/20日相对强度 + 距近期高点位置 | 25% | 30% |
| D3 板块共振 | `board_rotation` 快照 JSON | 所属板块强度分 + 发酵/高潮阶段 | 20% | 0%（降级时剔除，权重重分配）|
| D4 量能形态 | `historical_kline`（日线口径） | 日均量比 + 近5日成交量斜率 | 20% | 25% |

**D3 降级权重重分配规则**（`board_heat_latest.json` 缺失时）：
- D3 权重 20% 按比例分给 D1(+10%)、D2(+5%)、D4(+5%)，阈值同步调整为 RED≥78、GREEN≤32。
- `degraded=True` 标注在快照里，前端共振榜显示"板块维度暂不可用"提示。

### 2.4 信号灯逻辑（修复版）
```
# D3 在线时（正常模式）
共振分 = D1×0.35 + D2×0.25 + D3×0.20 + D4×0.20

# D3 降级时（三维模式，权重重分配）
共振分 = D1×0.45 + D2×0.30 + D4×0.25

# D2 数据不足时（新股/K线不足22日，权重重分配）
共振分(D3在线) = D1×0.47 + D3×0.27 + D4×0.27（标 d2_insufficient=True）
共振分(D3降级) = D1×0.60 + D4×0.40

🔴 红灯（主力进场）：共振分 ≥ 75(D3降级时78) 且 D1_state ∈ {吸筹,拉升}
🟢 绿灯（主力出场）：共振分 ≤ 30(D3降级时32) 且 D1_state = 出货
🟡 黄灯：其余状态
```

**vol_ratio 不作信号灯硬门槛**（修复5）：量能已在 D4 分里充分体现（`ratio_score × 0.6`）。在共振分之外再加 `vol_ratio > 1.2` 硬判断是对同一数据的双重过滤，会漏掉量能斜率强但当日量比稍低的票。若要保留量能门槛，以 D4 内部必要条件的形式实现：`vol_ratio < 0.5` 时 `d4_score` 强制上限 20 分，不在外层再加条件。

**阈值只读建议，不自动收紧**（修复4）：快照里记录 `signal_counts:{RED,YELLOW,GREEN}` 和 `suggested_threshold_adjustment`（RED>100 时建议 +3，RED<5 时建议 -3），由人工决定是否调整。阈值只能通过 `RESONANCE_RED_THRESHOLD` / `RESONANCE_GREEN_THRESHOLD` env 显式修改，**禁止运行时自动变更**，避免同日多轮间阈值漂移导致榜单不可比。

### 2.5 输出口径
- 每只票每轮输出：`resonance_score / signal / d1_score / d1_state / d1_continuity_rounds / d2_score / d3_score / d4_score / d4_vol_ratio / active_source / degraded / d3_degraded`
- D3 降级：权重重分配，阈值调整，`d3_degraded=True`，`d3_score=null`（不填 50 中性，避免污染分布）。

## 3. 技术方案

### 3.1 数据源与 IO 边界（修复版）

- **D1（修复6：IO 边界明确）**：service 层 `run_resonance_once` 开头批量查一次 `tier_flow_snapshot` 当日历史，按 code 聚合好 `continuity_rounds` 字典（`{code: int}`），传给 `d1_score` 纯函数。纯函数只接收已计算好的整数，不做任何 IO。测试时直接 mock 这个字典，无需 mock 数据库。
- **D1（修复1：执行顺序约束）**：`run_resonance_once` 开头检查 `tier_flow_snapshot` 当日数据条数，若为 0 则先调用 `run_tier_flow_once(force=True)` 补跑一次。**调度约束**：daily-screening 流水线里 `tier_flow` 必须排在 `resonance` 之前；若并行跑，resonance 需等待 tier_flow 完成后再启动。
- **D2/D4（共享 K 线）**：service 层对每只票拉一次 `fetch_historical(symbol, days=60)`，把同一份 `closes/highs/vols` 切片分别传给 `d2_score` 和 `d4_score`，不重复采集。
- **D3（修复3：匹配修复）**：`board_heat_latest.json` 由 05 方案 service 层生成时，**必须**在每个板块条目里写入 `codes: [code1, code2, ...]` 成分股列表（这是 15/05 两方案的接口约定，需同步写进 05 方案施工文档）。若 05 方案未能提供 `codes` 字段，`d3_score` 降级改查 `board_stock_daily` 表：`code → board_code → board_daily.score`，需要传入 `db_session`，此路径标 `d3_source="db"`。两路都不可用时 `d3_degraded=True`，按 §2.3 权重重分配。

### 3.2 算法（indicators.py 纯函数，所有除法防 0）

```python
# D1：资金主力分
def d1_score(smart_ratio: float, state: str, continuity_rounds: int = 0) -> float:
    """
    smart_ratio: (super_net + big_net) / total_amount，clip 到 [-0.05, 0.05]
    state: "吸筹" / "拉升" / "出货" / "观望"
    continuity_rounds: 今日连续处于同一 state 的轮次数（从 tier_flow_snapshot 查）
    """
    # 基础分：smart_ratio 归一化到 [0, 100]
    base = (min(max(smart_ratio, -0.05), 0.05) + 0.05) / 0.10 * 100
    # state 修正
    state_bonus = {"拉升": 15, "吸筹": 10, "观望": 0, "出货": -20}.get(state, 0)
    # 持续性加成：连续 N 轮同向，最多加 10 分（每轮 +1，上限 10）
    continuity_bonus = min(continuity_rounds, 10)
    return min(max(base + state_bonus + continuity_bonus, 0), 100)

# D2：价格动量分（修复版：数据不足返回 None，不返回 50）
def d2_score(closes: list, highs: list) -> Optional[float]:
    """
    数据不足（len(closes) < 22）时返回 None，由 compute_resonance 做权重重分配。
    不返回 50 的原因：50 会以 50×0.25=12.5 分正向贡献共振分，新股会被错误推进 RED 榜。
    归一化区间（全进 config，RESONANCE_* env 覆盖）：
      ret_5:    [-0.05, +0.05]  → [0, 100]
      ret_20:   [-0.10, +0.10]  → [0, 100]
      dist_high:[0, 0.15]       → [100, 0]（越近高点越高分）
    内部权重：ret_5×0.35 + ret_20×0.40 + dist_high×0.25
    """
    if len(closes) < 22 or len(highs) < 20:
        return None  # 数据不足，调用方做权重重分配，不用中性值污染分布
    ret_5  = (closes[-1] - closes[-6])  / closes[-6]  if closes[-6]  > 0 else 0
    ret_20 = (closes[-1] - closes[-21]) / closes[-21] if closes[-21] > 0 else 0
    high20 = max(highs[-20:])
    dist   = (high20 - closes[-1]) / high20 if high20 > 0 else 0
    s5  = (min(max(ret_5,  -0.05), 0.05) + 0.05) / 0.10 * 100
    s20 = (min(max(ret_20, -0.10), 0.10) + 0.10) / 0.20 * 100
    sd  = max(1 - dist / 0.15, 0) * 100
    return s5 * 0.35 + s20 * 0.40 + sd * 0.25

# D3：板块共振分（修复版：两路匹配，均不可用时返回 None 而非 50）
def d3_score(code: str, board_heat_json: dict,
             db_session=None) -> tuple[Optional[float], bool, str]:
    """
    返回 (score, degraded, source)。
    匹配路径（按优先级）：
      1. board_heat_latest.json 里每个板块条目的 codes 字段（05方案需写入，接口约定见下）
      2. board_stock_daily 表查询（需传入 db_session）
      3. 两路均不可用 → (None, True, "unavailable")
    score=None 时由调用方按 §2.3 权重重分配，不填 50（理由同 D2）。

    【05 方案接口约定】board_heat_latest.json 每条 item 需包含：
      {"board_code": ..., "board_name": ..., "score": ..., "codes": ["000001", ...]}
    若 05 方案未能提供 codes 字段，d3_score 自动降级到路径 2（db 查询）。
    """
    # 路径 1：快照 JSON 匹配
    if board_heat_json:
        items = board_heat_json.get("items") or []
        matched = [i.get("score", 0) for i in items
                   if code in (i.get("codes") or [])]
        if matched:
            return min(max(max(matched), 0), 100), False, "snapshot"
    # 路径 2：board_stock_daily 表查询
    if db_session is not None:
        try:
            from backend.db.plugin_models import BoardStockDaily, BoardDaily
            row = (db_session.query(BoardDaily.score)
                   .join(BoardStockDaily,
                         BoardDaily.board_code == BoardStockDaily.board_code)
                   .filter(BoardStockDaily.code == code)
                   .order_by(BoardDaily.score.desc())
                   .first())
            if row and row.score is not None:
                return min(max(float(row.score), 0), 100), False, "db"
        except Exception:
            pass
    return None, True, "unavailable"
    items = board_heat_json.get("items") or []
    # 按个股行业/概念匹配，取最高板块分归一化
    matched = [i.get("score", 0) for i in items if code in (i.get("codes") or [])]
    if not matched:
        return None, True
    raw = max(matched)
    normalized = min(max(raw / 100.0 * 100, 0), 100)
    return normalized, False

# D4：量能形态分（日线口径，页面必须标注"基于日线数据"）
def d4_score(vols: list) -> tuple[float, float]:
    """
    返回 (score, vol_ratio)。vol_ratio 供信号灯硬判断（>1.2 放量，<0.8 缩量）。
    日均量比 = vol[-1] / mean(vol[-6:-1])，与盘中量比口径不同，页面标注说明。
    """
    if len(vols) < 7:
        return 50.0, 1.0
    avg5 = sum(vols[-6:-1]) / 5 if sum(vols[-6:-1]) > 0 else 1
    vol_ratio = vols[-1] / avg5 if avg5 > 0 else 1.0
    # 5日量能斜率归一化
    slope = _linear_slope(vols[-5:])
    slope_norm = min(max((slope / avg5 + 1) / 2 * 100, 0), 100)  # 斜率归一化到 0-100
    # 量比分：clip 到 [0.5, 2.5]
    ratio_score = (min(max(vol_ratio, 0.5), 2.5) - 0.5) / 2.0 * 100
    return ratio_score * 0.6 + slope_norm * 0.4, vol_ratio

def _linear_slope(values: list) -> float:
    """最小二乘斜率，序列不足 2 个点返回 0。"""
    n = len(values)
    if n < 2:
        return 0.0
    x_mean = (n - 1) / 2
    y_mean = sum(values) / n
    num = sum((i - x_mean) * (v - y_mean) for i, v in enumerate(values))
    den = sum((i - x_mean) ** 2 for i in range(n))
    return num / den if den > 0 else 0.0
```

**共振分合成（service 层）**：

```python
def compute_resonance(d1: float, d2: Optional[float], d3_result: tuple,
                      d4_result: tuple, weights: dict = None) -> dict:
    """
    修复版共振分合成：
    - 去掉 vol_ratio 硬门槛（量能已在 D4 里体现，双重过滤会漏票）
    - D2=None 时权重重分配，不填 50（避免新股误推 RED）
    - 阈值只读建议，不自动收紧（避免同日多轮漂移）
    """
    d3_val, d3_degraded, d3_source = d3_result
    d4_val, vol_ratio = d4_result

    d2_insufficient = d2 is None

    if d3_degraded and d2_insufficient:
        # 两个维度都缺：D1×0.60 + D4×0.40
        score = d1 * 0.60 + d4_val * 0.40
        red_t, green_t = 80, 34
    elif d3_degraded:
        # D3 缺：D1×0.45 + D2×0.30 + D4×0.25
        score = d1 * 0.45 + d2 * 0.30 + d4_val * 0.25
        red_t, green_t = 78, 32
    elif d2_insufficient:
        # D2 缺：D1×0.47 + D3×0.27 + D4×0.27（D2 的 25% 分给 D1+15、D4+10）
        score = d1 * 0.47 + d3_val * 0.27 + d4_val * 0.27
        red_t, green_t = 76, 31
    else:
        # 正常四维
        score = d1 * 0.35 + d2 * 0.25 + d3_val * 0.20 + d4_val * 0.20
        red_t, green_t = 75, 30

    score = round(min(max(score, 0), 100), 2)

    # 信号灯：去掉 vol_ratio 硬门槛，量能已在 D4 分里体现
    if score >= red_t:
        signal = "RED"
    elif score <= green_t:
        signal = "GREEN"
    else:
        signal = "YELLOW"

    # 只读建议，不自动收紧（阈值只能通过 env 显式修改）
    suggested_adj = None
    # 调用方统计全市场 RED 数量后再判断，此处不做自动修改

    return {
        "resonance_score": score, "signal": signal,
        "d3_degraded": d3_degraded, "d3_source": d3_source,
        "d2_insufficient": d2_insufficient,
        "vol_ratio": round(vol_ratio, 3),
        "red_threshold": red_t, "green_threshold": green_t,
    }
```

### 3.3 调度
- 盘后 15:10 随 daily-screening 触发一次（云端 Render cron）。
- 盘中随 principal-capital-scan 5分钟循环可选触发（`d2/d4` 用最近 K 线缓存，不每次重拉）。

### 3.4 性能
全市场 5000+ 只每只拉 60 日 K 线网络开销大：
1. 先从 `tier_flow` 快照做 D1 粗筛，只对 `state ∈ {吸筹,拉升,出货}` 的票（约 500-1500 只）拉 K 线。
2. K 线批量并发：`asyncio.gather + Semaphore(20)` 限流。
3. K 线结果缓存当日，盘中多轮不重复拉。

## 7. 测试与验收

## 9. 风险与限制

- 共振分阈值是经验初值，需积累 20+ 交易日样本后结合胜率回测校准（见 06 因子实验室）。
- 信号仅为辅助参考，不构成投资建议；页面必须显示此声明。
