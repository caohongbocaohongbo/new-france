# 14 交易日历基础设施 — 产品开发技术方案

## 1. 目标与定位

补齐全局地基：当前判"是否交易日"只用 `weekday() < 5`（周末），**不识别法定节假日、调休、半日市**。接入真实交易日历后，一次投入让 01/03/04/10 与筛选链路的"次日 / T+N / 尾盘 / 回补天数"口径全部精确。

优先级：**P0（地基优先，先于第一波功能）**。akShare 已是依赖，改造面小、全局受益。

## 2. 产品方案

### 2.1 用户场景
不直接产出页面业务，是被其它功能与调度依赖的底层能力。对用户可见的表现：休市日不再误判为交易日、T+N 表现口径准确、节假日调度不空跑。

### 2.2 能力清单
- `is_trading_day(d)`：某日是否交易日（含节假日 / 调休）。
- `next_trading_day(d, n=1)` / `prev_trading_day(d, n=1)`：前后第 n 个交易日。
- `trading_days_between(start, end)`：区间交易日数（替代"+10 自然日缓冲"硬凑）。
- `n_trading_days_later(d, n)`：T+N 标签口径（供 01/03 收益标签用）。

### 2.3 输出口径
- 交易日全集来自权威源，节假日 / 调休以交易所公布为准。
- 半日市（如某些节前）当前仅标记 `is_trading_day=True`，时段细分留待后续，不在本期实现。

## 3. 技术方案

### 3.1 数据源
- akShare `tool_trade_date_hist_sina()`：返回历史 + 未来交易日列表，免费、覆盖足够。
- Tushare `trade_cal`（若配置 TOKEN）作交叉校验兜底。

### 3.2 缓存与降级
- 首次拉取后缓存 `data/trading_calendar.json`（含 `dates` 列表 + `fetched_at` + `source`）。
- TTL 按天：同一交易日内命中缓存不重复拉；跨日或缺失未来日期时刷新。
- **降级兜底**：网络失败且缓存过期时，回退到 `weekday() < 5` 判断，并在返回结构标 `degraded=True`，绝不因日历拉取失败而崩调度。

### 3.3 受控改造（关键）
本方案**必须改动既有文件**（这是地基的特殊性），改造原则：只把日期判断委托给新模块，**保持函数签名与返回结构不变**，加降级兜底。
- `backend/api/router_system.py:26`：`is_trading_day = now.weekday() < 5` → `is_trading_day = trading_calendar.is_trading_day(now.date())`。
- `backend/services/data_backend/trading_session.py:18-19`：落实 TODO，`weekday() >= 5` 判断替换为日历判断。
- `backend/services/screening_service.py:186`：`+10 自然日缓冲` 可改用 `trading_days_between` 精确取历史窗口（可选，先保留兜底）。

## 4. 数据存储方案

- 文件缓存：`data/trading_calendar.json`
  ```json
  {"source": "akshare", "fetched_at": "2026-08-26T...", "dates": ["2026-01-02", "..."], "degraded": false}
  ```
- 不新增 SQLite 表；交易日全集体量小，文件缓存足够。
- 提交 `data-snapshots` 分支，Render 拉不到 akShare 时读快照兜底。

## 5. 数据读取方案

- 内部调用为主，通过 `backend/services/trading_calendar.py` 函数直接引用。
- 可选暴露 `GET /api/v1/system/trading-calendar?year=`：返回某年交易日列表，供前端日历标注。
- 模块级内存缓存 + 文件缓存双层，调用零网络开销。

## 6. 与现有系统集成

- **新建** `backend/services/trading_calendar.py`（基础设施，非 plugin，供全局复用）。
- **受控改造** §3.3 三处既有文件（仅委托日期判断，签名不变）。
- 时区统一 `BEIJING_TZ`；所有 akShare 调用带 timeout；降级不崩。

## 7. 测试与验收

- 单元测试：已知节假日（如国庆 / 春节）`is_trading_day=False`；调休上班日 `=True`；`next/prev_trading_day` 跨节假日正确跳。
- 降级测试：mock akShare 抛错 + 缓存过期 → 回退 weekday 且 `degraded=True`，不抛异常。
- 回归测试：改造后 `trading_session_status` 返回结构字段不变（`is_trading_day/is_trading_hours/market_session/market_status_text`）。
- 验收：近一年含节假日的日期判断与交易所日历 100% 一致。

## 8. 上线与运维

- 首次上线预热拉取当年 + 次年交易日，写入缓存并提交 `data-snapshots`。
- 每年末或缓存缺失次年数据时自动刷新。

## 9. 风险与限制

- akShare 源偶发不可用 → 已有降级兜底，不阻断主链路。
- 半日市时段细分本期不做，仅保证"是否交易日"精确。
- 交易所临时休市公告有滞后可能，必要时人工覆盖缓存文件。

## 10. 里程碑

1. M1：`trading_calendar.py` + 文件缓存 + 降级兜底 + 单测。
2. M2：受控改造三处入口，回归验证结构不变。
3. M3：（可选）`screening_service` 历史窗口改精确 + 前端日历标注接口。
