# 10 涨停封单强度与开板回封监测 — 产品开发技术方案

## 1. 目标与定位

对标 Level-2“涨停封单”页面，输出：
- 封单额、封单量、封成比（封单额 / 流通市值）；
- 封单变化曲线（盘中每 5 分钟）；
- 开板预警（封单骤减、炸板）；
- 回封概率（历史同类型炸板后回封比例）。

优先级：P1。短线和打板参考直接拉满。

## 2. 产品方案

### 2.1 页面模块
- 涨停封单榜：按封单额 / 封成比排序。
- 个股封单时间线：封单额、炸板次数、封板状态。
- 预警：封单骤减 / 开板 / 回封。

### 2.2 输出口径
- 封单额 = 涨停价卖一挂单量 × 价格（本地 pytdx 近似）。
- 封成比 = 封单额 / 流通市值。
- 回封概率 = 历史炸板后当日 / 次日回封比例。

## 3. 技术方案

### 3.1 数据源
- 东财涨停池：扩展解析 `封板资金 / 封单量 / 首次封板时间 / 最后封板时间 / 开板次数` 字段。
- 本地 pytdx：涨停股五档中 `ask1` 量即封单量近似。
- 历史涨停池 + 次日表现做回封概率回测。

### 3.2 算法
- 每 5 分钟采样封单，做斜率变化检测：封单量 10 分钟下降 > 50% 且未打开 → 预警。
- 炸板识别：`break_count` 增加或价格跌停不封。
- 回封概率：历史同连板高度 / 同炸板次数的回封比例。

### 3.3 调度
- 盘中 09:25–15:00 每 5 分钟，复用涨停池与资金流扫描。

## 4. 数据存储方案

```sql
CREATE TABLE zt_seal_snapshot (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  date TEXT NOT NULL,
  hhmm TEXT NOT NULL,
  code TEXT NOT NULL,
  seal_amount REAL,
  seal_vol REAL,
  break_count INTEGER,
  first_seal_time INTEGER,
  last_seal_time INTEGER,
  is_sealed INTEGER
);
CREATE INDEX idx_zt_seal ON zt_seal_snapshot(date, hhmm);
CREATE INDEX idx_zt_seal_code ON zt_seal_snapshot(code, date);
```

快照：`reports/zt_seal_latest.json`。

## 5. 数据读取方案

- `GET /api/v1/zt-seal/latest`：读 JSON。
- `GET /api/v1/zt-seal/{code}?date=`：走 `idx_zt_seal_code`。
- 全涨停池覆盖，5 分钟级刷新，页面秒开。

## 6. 与现有系统集成

- 扩展 `backend/agents/layer1_data_collector/sources/eastmoney_zt.py` 字段解析。
- 新增 `backend/plugins/zt_seal/`，复用 `smart_money_radar` 本地五档与邮件。

## 7. 测试与验收

- 封单字段解析：缺失字段不参与计算。
- 斜率预警：封单骤减触发、正常波动不触发。
- 验收：涨停池全量有封单数据（可用源字段），开板 / 回封事件准确。

## 8. 上线与运维

- 盘中扫描 + 盘后最终态。
- 生成物提交 `data-snapshots`。

## 9. 风险与限制

- 本地五档只能近似封单量，与交易所精确封单有偏差。
- 东财封单字段若缺失，需明确空态，不得编造。

## 10. 里程碑

1. M1：涨停池封单字段扩展。
2. M2：封单采样 + 斜率预警。
3. M3：回封概率 + 页面。
