> 基于 2026-09-08 grill 定稿文档（含 6 处补充），按风险等级降序排列问题修复点。  
> 本报告对应施工交付物的验收，不替代单测运行结果。

## 问题修复点（风险降序）

### P1 — 高风险：云端兜底无实现规格（已修复 DIFF-1）

**问题**：`read_snapshot_resilient` 被 §2/§3/§4 反复引用，但原文无签名、无超时、无失败返回结构、无 URL 拼接规则。施工时各实现者会写出不同版本，云端兜底行为不可预期，极端情况引发 500 或无限阻塞。

**修复**：§2.4 补入完整规格——5s 超时、4 步执行流程（本地→data_backend→chip 拦截→remote）、失败返回 `{"status":"no_data","_source":"unavailable","items":[],"reason":"..."}`、URL 拼接公式、磁盘 TTL 缓存路径。chip 专属拦截防止无效网络请求。

**验收命令**：
```bash
# 模拟云端：删除本地快照，验证兜底返回而非抛异常
rm -f reports/tech_indicators_latest.json
python3 -c "
from backend.plugins.common import read_snapshot_resilient
r = read_snapshot_resilient('tech_indicators')
assert r.get('_source') in ('snapshot', 'unavailable'), r
print('_source:', r['_source'])
print('status:', r.get('status'))
"
```

### P2 — 高风险：无前视单测无法通过（已修复 DIFF-6）

**问题**：`refresh_perf` 伪代码注释"按 trading_calendar 交易日序列"，来源不明。如果依赖外部日历 API 或 akshare，单测必须联网或需要 mock，且 target 计算若用自然日会导致"无前视"断言在停牌周围失效。

**修复**：§7.4 补入 `trading_days_after(bars, anchor_date, k)` 函数规格——直接从 K 线 bar 序列推导，东财 `fetch_historical` 返回值本身即交易日序列，无外部依赖。停牌处理：bars 不足 k 条时 `data_missing=1`。伪代码同步更新为调用该函数。

**验收命令**：
```bash
# 无前视单测：删除 R 之后的 bar，验证 filled 字段不变
python3 -m pytest backend/plugins/smart_picker_hub/tests/test_perf.py \
  -k "no_lookahead" -v --no-header
# 预期：全部 PASSED，无网络请求
```

### P3 — 中风险：`charts` 字段结构未定义（已修复 DIFF-2）

**问题**：§4.8 写入快照 `charts.{code}`，§6.3 返回图表数据，但两者字段结构从未对齐定义。前端若按 §6.3 结构解析快照内嵌 charts，字段不一致会导致图表渲染失败，且无单测可覆盖。

**修复**：§4.9（新增）明确 `charts.{code}` 与 `/chart` 响应内层同构，给出完整字段树（records/series 五个子对象），补充体积估算（40 只 × 80 bar ≈ 20KB）及 SSE 广播排除规则。

**验收命令**：
```bash
# 验证快照内嵌 charts 与端点响应结构一致
python3 -c "
import json, requests
snap = json.load(open('reports/smart_picker_latest.json'))
code = list(snap.get('charts', {}).keys())[0]
snap_chart = snap['charts'][code]
api_chart = requests.get(f'http://localhost:8000/api/v1/smart-picker/{code}/chart').json()
assert set(snap_chart.keys()) == set(api_chart.keys()) - {'status','code','cached'}, \
    f'结构不一致: snap={set(snap_chart.keys())} api={set(api_chart.keys())}'
print('charts 结构一致，code:', code)
"
```

### P4 — 中风险：历史查询响应格式未定义（已修复 DIFF-3）

**问题**：§6.2 提到 `?date=` 走 SQLite `raw_json` 反序列化，但没有写响应 JSON 结构。前端详情追溯和 `picker_perf_daily` 的历史对账均依赖此格式；无规格则单测 mock 无法编写。

**修复**：§6.2 补入两种响应——命中时 `{status:"ok", source:"sqlite", item:{...完整行...}}`；未命中时 `{item:null, note:"no_hit_on_date"}`。

**验收命令**：
```bash
# 查询历史有数据的日期（先确认 smart_picker_hits 表有记录）
python3 -c "
import sqlite3, json
conn = sqlite3.connect('data/france.db')
row = conn.execute('SELECT date, code FROM smart_picker_hits LIMIT 1').fetchone()
if row:
    date, code = row
    import requests
    r = requests.get(f'http://localhost:8000/api/v1/smart-picker/{code}?date={date}').json()
    assert r['status'] == 'ok', r
    assert r.get('source') == 'sqlite', r
    assert r['item'] is not None, r
    print(f'历史查询 OK: {code} @ {date}')
else:
    print('smart_picker_hits 无数据，跳过')
"
```

### P5 — 低风险：并发写安全无保障（已修复 DIFF-4）

**问题**：`--run-smart-picker-all`（cron 15:10）与 `--run-smart-picker-hub`（手动调试）并发时，`db_delete + db_append` 非原子，可能产生部分行数据或重复行。

**修复**：§7.2 补充 lockfile 方案——`run_smart_picker_hub_once` 入口写 `reports/.hub.lock`，第二个进程检测到 lock 即跳过并记日志。文档明确"不支持并发"为设计决策。

**验收命令**：
```bash
# 验证 lockfile 机制：先后台启动 hub，再立即再启动一次，第二次应记日志并退出
python3 -m backend.main --run-smart-picker-hub &
sleep 1
python3 -m backend.main --run-smart-picker-hub
# 预期：第二次进程日志含 "hub.lock detected, skipping" 类似字样，不写 DB
```

### P6 — 低风险：体积预算未计 charts + 提交脚本兼容性未验证（已修复 DIFF-5）

**问题**：原预算"≤120KB（全字段合并 98KB）"忽略了 `charts` 的 ~20KB，总计 ~118KB 仍满足但数字不准确。`commit_screening_data.sh` "0 改动"结论未给出验证路径。

**修复**：§7.3 体积估算细化为 items 98KB + charts 20KB = ~118KB；补充"施工时需验证脚本 glob 覆盖两个 smart_picker 路径"的明确提示。

**验收命令**：
```bash
# 1. 验证快照体积
python3 -c "
import os
size = os.path.getsize('reports/smart_picker_latest.json')
print(f'smart_picker_latest.json: {size/1024:.1f} KB')
assert size <= 120 * 1024, f'超出 120KB 预算: {size}'
print('体积验收通过')
"

# 2. 验证 commit_screening_data.sh 覆盖范围（dry-run 模式）
grep -n 'rsync\|cp\|reports' scripts/commit_screening_data.sh | head -20
# 确认 reports/ 整目录或 reports/data_backend/ 均被覆盖
```

## 验收汇总

| 优先级 | 问题 | 修复位置 | 验收命令节 |
|---|---|---|---|
| P1 高 | `read_snapshot_resilient` 无规格 → 云端兜底不可施工 | §2.4 新增 | M0 + 云端抽查 |
| P2 高 | 交易日历来源不明 → 无前视单测无法通过 | §7.4 重写 | M2 无前视 |
| P3 中 | `charts` 字段结构未定义 → 前端图表渲染依赖不明 | §4.9 新增 | M3 图表接口 |
| P4 中 | 历史查询响应格式缺失 → 追溯单测无 mock 基础 | §6.2 补充 | M2 入库验证 |
| P5 低 | 并发写无保障 → 极端情况数据竞争 | §7.2 追加 | M2 全链路 |
| P6 低 | 体积预算缺 charts 估算 + 脚本兼容性未验证 | §7.3 细化 | M4 压测 |
