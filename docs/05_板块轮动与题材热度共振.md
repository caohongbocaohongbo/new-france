# 05 板块轮动与题材热度共振 — 产品开发技术方案

## 1. 目标与定位

补齐题材维度：行业 / 概念热度榜、主线题材识别、题材发酵阶段判断。回答“今天的主线是不是在走弱、明天该不该继续做”。

优先级：P1。覆盖率高、时效强，机构与游资做题材轮动的标准视图。

## 2. 产品方案

### 2.1 页面模块
- 板块热度榜：涨幅、资金净流入、涨停家数、涨停占比、连板高度。
- 主线候选：同一概念内涨停家数 ≥ 2 且出现连板。
- 题材阶段：启动 → 发酵 → 高潮 → 分歧 → 退潮。

### 2.2 输出口径
- 板块分 = z(涨幅) + z(资金净流入) + log(1+涨停家数)×w + 最高连板×w + 涨停占比×w。
- 主线确认：连续 2 天在榜且涨停家数不衰减。

## 3. 技术方案

### 3.1 数据源
- 东财行业 / 概念板块行情 + 成分股。
- 涨停池已有 `所属行业`，补充概念映射。
- akShare 板块接口兜底。

### 3.2 算法
- 板块强度用 z-score 加权利，避免不同量纲不可比。
- 发酵阶段用“涨停家数变化 + 板块内涨跌比 + 龙头是否炸板”做状态机，与 `smart_money_radar` 四阶段同构。

### 3.3 调度
- 盘中每 5 分钟（资金流扫描时顺便算），盘后 15:10 出最终态。

## 4. 数据存储方案

```sql
CREATE TABLE board_daily (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  date TEXT NOT NULL,
  board_code TEXT NOT NULL,
  board_name TEXT,
  board_type TEXT,
  change_pct REAL,
  net_inflow REAL,
  zt_count INTEGER DEFAULT 0,
  max_height INTEGER DEFAULT 0,
  zt_ratio REAL,
  score REAL,
  stage TEXT
);
CREATE INDEX idx_board_date ON board_daily(board_code, date);

CREATE TABLE board_stock_daily (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  date TEXT NOT NULL,
  board_code TEXT NOT NULL,
  code TEXT NOT NULL,
  name TEXT,
  is_zt INTEGER DEFAULT 0,
  is_leader INTEGER DEFAULT 0,
  height INTEGER DEFAULT 0
);
CREATE INDEX idx_board_stock ON board_stock_daily(code);
```

快照：`reports/board_heat_latest.json`。

## 5. 数据读取方案

- `GET /api/v1/board/latest`：读 JSON 快照。
- `GET /api/v1/board/{board_code}/history`：走 `idx_board_date`。
- `GET /api/v1/board/stock/{code}`：个股-板块关系。

## 6. 与现有系统集成

- 新增 `backend/plugins/board_rotation/`。
- 复用 `eastmoney_zt` 的行业字段与 `principal_capital` 的资金流。

## 7. 测试与验收

- z-score 与权重计算测试。
- 主线确认逻辑：连续 2 天 + 涨停家数不衰减。
- 验收：热门板块与公开软件口径一致，阶段切换可解释。

## 8. 上线与运维

- 盘后每日任务 + 盘中扫描双跑。
- 生成物提交 `data-snapshots`。

## 9. 风险与限制

- 概念成分股口径不同源会不一致，需固定概念映射版本。
- 板块资金流为估算值，需与个股资金流交叉验证。

## 10. 里程碑

1. M1：板块行情 + 成分股采集。
2. M2：板块分 + 主线识别。
3. M3：阶段状态机 + 页面。
