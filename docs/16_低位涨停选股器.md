# 16 低位涨停选股器 — 产品开发技术方案

## 1. 目标与定位

每个交易日收盘后，从全市场自动筛选出**当前处于低位、且近期有过涨停记录**的股票，作为次日重点关注候选池。逻辑是：有涨停能力（主力运作历史）+ 现在回到低位（筹码便宜）= 再次启动的概率更高。

优先级：**P0（云端盘后、无本地依赖、数据现成）**。是两个新功能中最先落地的。

## 2. 产品方案

### 2.1 用户场景
每日 15:10 自动跑，15:30 前结果出现在 Dashboard 和邮件；次日 09:00 开盘前可查。用户看到今日低位涨停候选池，决定哪些票次日值得重点关注或加入观察池。

### 2.2 筛选条件（修复版）

**低位判断（回撤必须满足，另两维满足其一）**：
1. **距近 60 日最高收盘价回撤 ≥ 25%**（必要条件，有涨停记录的票从高位回落即此形态）
2. **现价在近 120 日价格区间 ≤ 30% 分位** OR **现价 ≤ MA20**（满足其一即可）

> 三维全过逻辑会误杀"从高位涨停后回落"的典型形态（回撤深但百分位未到低位，因整体区间被拉高）。改为"回撤必须 AND 另两维满足其一"，能正确抓住此类形态。

**涨停历史（四级降级，优先级从高到低）**：
1. `limit_up_daily` 表（01方案落库）——覆盖近 250 交易日，口径最准
2. Tushare `limit_list_d`（有 `TUSHARE_TOKEN` 时）——历史回补，批量拉取
3. akShare `stock_zt_pool_em` 按日循环——最多拼 30 日，带限速保护（`asyncio.sleep(0.3)` 每次请求后）
4. 三者都拿不到时：`zt_available=False`，该票仍可入选但标注"无涨停历史数据"，不因数据缺失而过滤掉

**额外过滤**（提升信号质量）：
- 剔除 ST / 科创板 688 / 创业板 300-301（复用 `_base_filter`）
- 流通市值 20-300 亿（可 `LOW_POSITION_*` env 覆盖）
- 当日成交额 > 5000 万（排除僵尸股）

### 2.3 输出口径
每只入选票输出：
- 低位数据：`pullback_pct`（回撤%）、`price_percentile`（百分位）、`below_ma20`（是否在均线下）
- 涨停历史：`last_zt_date`（最近涨停日）、`zt_count_250d`（近250交易日涨停次数）、`zt_source`（数据来源）、`zt_available`（是否有涨停历史数据）
- 基础面：`price / market_cap / turnover / total_amount`
- 综合分：`low_score`（0-100，越高表示低位越深+涨停质量越好）
- 动能惩罚：`accel_down_penalty`（近5日加速下跌的惩罚分，体现在 `low_score` 中而非硬性剔除）

### 2.4 综合打分（0-100，供排序）

```
# 三个子项各自归一化到 [0, 1] 后加权，最终乘 100
pullback_norm   = min(|pullback_pct| / 0.60, 1.0)           # 回撤深度，60%封顶
percentile_norm = 1 - min(price_percentile / 0.30, 1.0)     # 百分位越低越高分
zt_norm         = min(zt_count_250d, 5) / 5                  # 涨停次数，5次封顶

# 近5日加速下跌惩罚（不作硬性过滤，作负向因子）
accel_penalty = accel_down_factor(closes[-6:])               # 返回 0.0-0.2

low_score = (pullback_norm × 0.45 + percentile_norm × 0.30 + zt_norm × 0.25
             - accel_penalty) × 100
low_score = max(0, min(100, low_score))
```

权重（`LOW_POSITION_PULLBACK_W / PERCENTILE_W / ZT_W`）全进 config，env 可覆盖。

## 3. 技术方案

### 3.1 数据源
- K 线（低位计算）：`historical_kline.fetch_historical(symbol, days=130)` → `日期/收盘/最高/最低/成交量/换手率`。**130 日足够覆盖 120 日百分位 + 20 日均线 + 5 日斜率，比 250 日减少约 46% 的请求体积。**
- 涨停历史（四级降级，按顺序尝试）：
  1. `plugin_models.LimitUpDaily`（`limit_up_daily` 表，01方案落库）——近 250 交易日，口径最准
  2. Tushare `limit_list_d`（有 `TUSHARE_TOKEN` 时）——历史回补，全市场批量拉取
  3. akShare `stock_zt_pool_em` 按日循环——最多拼 30 日，每次请求后 `asyncio.sleep(0.3)` 限速保护
  4. 三者均不可用：`zt_available=False`，票仍可入选但标注，不因数据缺失而过滤
- 全市场粗筛：`fetch_market_fund_flow_resilient:228` 返回的 `price / total_amount / change_pct`，用于过滤僵尸股和受限市场，**不依赖它提供涨停历史**。

### 3.2 算法（indicators.py 纯函数，所有除法防 0）

```python
def pullback_from_high(closes: list, window: int = 60) -> Optional[float]:
    """距近 window 日最高收盘价的回撤幅度（负值，如 -0.30 = -30%）。"""
    if len(closes) < window or closes[-1] is None:
        return None
    high = max(closes[-window:])
    return (closes[-1] - high) / high if high > 0 else None

def price_percentile(closes: list, window: int = 120) -> Optional[float]:
    """现价在近 window 日价格区间的百分位（0-1，0=最低，1=最高）。"""
    if len(closes) < window:
        return None
    w = closes[-window:]
    lo, hi = min(w), max(w)
    return (closes[-1] - lo) / (hi - lo) if hi > lo else 0.5

def is_below_ma(closes: list, period: int = 20) -> Optional[bool]:
    """现价是否在 MA{period} 下方。"""
    if len(closes) < period:
        return None
    return closes[-1] < sum(closes[-period:]) / period

def is_low_position(closes: list) -> tuple[bool, dict]:
    """
    低位判断（修复版）：回撤必须满足，另两维满足其一即可。
    纯三维全过逻辑会误杀"从涨停高位回落"的典型形态（回撤深但120日百分位
    因整体区间被拉高而未到低位），改为 AND-OR 结构正确覆盖此类票。
    """
    pb = pullback_from_high(closes, 60)
    pp = price_percentile(closes, 120)
    bm = is_below_ma(closes, 20)
    detail = {"pullback_pct": pb, "price_percentile": pp, "below_ma20": bm}
    if pb is None:
        return False, detail
    # 回撤是必要条件；百分位和均线满足其一
    pullback_ok = pb <= -0.25
    second_ok = (pp is not None and pp <= 0.30) or (bm is True)
    return pullback_ok and second_ok, detail

def accel_down_factor(closes: list, window: int = 5) -> float:
    """
    近 window 日加速下跌惩罚因子（0.0-0.20）。
    不作硬性过滤：连续下跌票低位最深，直接剔除会误杀目标票型。
    改为负向加权写入 low_score，让排序靠后而不是消失。
    全部连续下跌 → 惩罚 0.20；无连续下跌 → 惩罚 0。
    """
    if len(closes) < window + 1:
        return 0.0
    days = closes[-(window + 1):]
    down_count = sum(1 for i in range(1, len(days)) if days[i] < days[i - 1])
    return round(down_count / window * 0.20, 4)

def compute_low_score(pullback_pct: float, price_pct: float,
                      zt_count: int, accel_penalty: float,
                      weights: dict = None) -> float:
    """
    综合低位分 0-100（统一归一化，三项子分各 0-1 再加权乘 100）。
    子项归一化区间：回撤封顶 60%，百分位 0-0.30，涨停次数 0-5 次。
    """
    w = weights or {"pullback": 0.45, "percentile": 0.30, "zt": 0.25}
    pb_norm = min(abs(pullback_pct) / 0.60, 1.0) if pullback_pct else 0.0
    pp_norm = max(1 - (price_pct / 0.30), 0.0) if price_pct is not None else 0.5
    zt_norm = min(zt_count or 0, 5) / 5
    raw = pb_norm * w["pullback"] + pp_norm * w["percentile"] + zt_norm * w["zt"]
    return round(max(0.0, min(1.0, raw - accel_penalty)) * 100, 2)
```

### 3.3 性能优化（关键，含耗时预估）

全市场 5000+ 只，两步过滤：

1. **粗筛**（用 `fetch_market_fund_flow_resilient` 快照，无额外请求）：
   - 剔除 ST / 688 / 300-301（`_base_filter`）
   - `total_amount < 5000万` 僵尸股剔除
   - 流通市值范围过滤
   - 粗筛后约剩 2500-3500 只

2. **精算**（对粗筛票并发拉 K 线）：
   - `historical_kline.fetch_historical(symbol, days=130)`（130 日覆盖 120日百分位 + 20日均线 + 5日斜率，比 250日减少约 46% 体积）
   - `asyncio.gather + Semaphore(30)` 并发（30 比之前方案的 20 提升约 33% 吞吐）
   - `return_exceptions=True` 隔离单票失败
   - **耗时预估**：3000 只 ÷ 30 并发 × 0.5s/请求 ≈ 50s，在 Render 免费层 HTTP 超时前可完成；若超时，`--max-kline-workers` 参数可降至 10（此时约 150s，需拆成两段跑）

3. **K 线当日缓存**（`data/low_position_kline_cache_{date}.parquet`，本地不提交 Render）：多次调用复用，次日清理。

## 4. 数据存储方案

```sql
CREATE TABLE low_position_hits (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  date TEXT NOT NULL,
  code TEXT NOT NULL,
  name TEXT,
  price REAL,
  pullback_pct REAL,        -- 距60日高点回撤（负值）
  price_percentile REAL,    -- 120日价格百分位（0-1）
  below_ma20 INTEGER,       -- 1=在MA20下方
  last_zt_date TEXT,        -- 最近涨停日期
  zt_count_250d INTEGER,    -- 近250交易日涨停次数
  market_cap REAL,
  turnover REAL,
  total_amount REAL,
  low_score REAL,           -- 综合低位分（供排序）
  zt_source TEXT            -- "db" 或 "zt_pool_fallback"
);
CREATE INDEX idx_low_pos ON low_position_hits(date);
CREATE INDEX idx_low_pos_code ON low_position_hits(code, date);
```

## 7. 测试与验收

- 低位三维边界：全过/全不过/各项边界值（回撤恰好 -25%/百分位恰好 0.3/恰好等于 MA20）；AND-OR 结构验证（回撤满足+百分位不满足+MA20满足 → 应入选）。
- 防除零：K 线不足窗口期时安全返回 `None` 不参与低位判断。
- `accel_down_factor`：近5日全跌返回 0.20，无连续下跌返回 0.0，不硬性剔除。
- 涨停历史四级降级：`limit_up_daily` 为空 → Tushare → akShare 30日 → `zt_available=False`，各级 `zt_source` 正确标注。
- 过滤：300/301/688/ST 被剔除；流通市值 <20亿 被剔除；**`show_gem=False / show_star=False` 默认不展示创业板/科创板**，`LOW_POSITION_*` env 打开时主板票排前。
- 性能：mock 验证粗筛后 K 线数量合理（< 3500 只），Semaphore(30) 限流生效。
- 验收：交易日 15:30 前产出 10-60 只，**主板（剔除 300/301/688/ST）> 3000 只扫通，结果中无创业板/科创板票（默认配置）**，`low_score` 范围 0-100，页面 <500ms。

## 9. 风险与限制

- 涨停历史：01 方案上线前 `limit_up_daily` 表数据可能为空，兜底路径仅覆盖近 30 日，250 日口径不准确 → 页面标注 `zt_source` 让用户知道数据来源。
- K 线批量拉取在 Render 免费层受东财限速，粗筛缩圈后仍可能慢 → 给 CLI 加 `--max-kline-workers` 参数，默认 20，允许降至 5。
- 低位不等于反弹，三维叠加条件严格但仍有假信号 → 页面和邮件必须显示"本结果仅为量化筛选，不构成投资建议"。
