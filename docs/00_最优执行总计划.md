## 0. 铁律（12 方案通用，违反即返工）

- **零污染主链路**：每个功能一律新增独立 `backend/plugins/<plugin>/` 目录，或在既有插件内**追加文件**。`backend/main.py` 只做三处改动（router try/except 注入 + argparse 加参数 + dispatch 分发），仿现有 `smart_money_radar` 接入块。**不改 `principal_capital` / `overnight_arbitrage` 核心逻辑**，完工用 `git diff` 自证。**例外：14 交易日历方案须受控改造 3 处既有入口（`router_system.py:26`、`trading_session.py:18-19`、可选 `screening_service.py:186`），这是明确授权的例外，见 §5-14。**
- **复用不重造**：市场过滤、邮件、去重、时段判断、资金流采集全部复用下方 §2 锚点，**禁止另写同名逻辑**。
- **时区统一**：`BEIJING_TZ = timezone(timedelta(hours=8))`，全程 `datetime.now(BEIJING_TZ)`，**禁裸 `datetime.now()`**。
- **健壮性**：所有 HTTP/pytdx/socket/SMTP 调用带 timeout；批量独立请求用 `asyncio.gather(..., return_exceptions=True)` + `asyncio.Semaphore` 限流；除法一律防 0。
- **数据真实性**：前端不渲染假数据；空数据出 `status=no_data`/空态，**不伪造评分、价格、封单、席位**。降级来源必须在 JSON 里显式标 `active_source` / `degraded`。
- **旁路先行**：新数据源默认旁路，只写 DB/API + `data/source_health.json`，`surfaces.email`/`surfaces.dashboard` 保持 `false`，达标后经 PR 打开（见 `DESIGN.md` 旁路数据源规范）。
- **部署边界**：云端盘后类（Render cron）与本地 pytdx 类（本机 daemon）严格分离，见 §3。高频盘口/逐笔原始数据**只落本地**，云端只同步聚合 JSON 快照到 `data-snapshots` 分支。

## 3. 部署轴（决定优先级的隐藏分界线）

| 轴 | 依赖 | 上线载体 | 方案 |
|---|---|---|---|
| **全局地基** | akShare 已依赖，被其它功能与调度引用 | 基础设施模块（非 plugin），随任意链路加载 | 14（交易日历） |
| **云端盘后** | 无本地依赖，东财/Tushare 盘后可得 | Render cron / GitHub Actions daily-screening | 01 02 09（盘后态）05（盘后态）03 06 |
| **云端盘中 5min** | 复用 principal-capital-scan 自循环 | Render + 冗余触发自循环 | 04 09（盘中态）05（盘中态）10（源字段路） |
| **本地 pytdx** | **本机开机 + 国内 IP + daemon 运行** | 本地 `--run-radar-daemon` + launchd | 07 08 13（集合竞价）10（五档路）11 12 |

**判据**：云端能独立跑的先做（参考性即时可用、不受"电脑要开着"约束）；本地 pytdx 类价值高但受实机约束，放在云端层稳定之后。
