# 国家队动向功能需求设计

## 目标

新增“国家队动向”菜单页面，并把国家队持仓披露和最新动作事件接入每日邮件。功能覆盖中央汇金、社保基金、证金公司三类主体，所有页面和邮件内容必须来自真实公开数据源，保留来源、报告期、公告日、采集时间，不用假数据或占位数据渲染。

## 数据真实性边界

十大股东、十大流通股东属于上市公司定期报告披露数据，不是每日实时持仓。系统每日执行的是“检查公开源是否出现新报告期、新公告日或持仓变动”，不能把未披露信息推断成每日交易动作。

页面和邮件需要明确展示：

- 持仓数据的报告期和公告日。
- 数据源名称和采集时间。
- 当前数据是否来自十大股东或十大流通股东。
- 如果公开源当天没有新披露，显示“未发现新的公开披露变化”。
- 如果数据源失败，显示“数据源暂不可用”，不回填假数据。

## 国家队主体定义

系统内置三类主体，并通过股东名称做确定性匹配：

- 中央汇金：匹配“中央汇金资产管理有限责任公司”“中央汇金投资有限责任公司”“中央汇金”。
- 证金公司：匹配“中国证券金融股份有限公司”“证金公司”“中国证金”。
- 社保基金：匹配“全国社保基金”“社保基金”。

匹配结果保存原始股东名称，前端不得只展示归一化主体名。

## 数据源

持仓披露主源使用东方财富股东分析原始接口：

- 接口地址：`https://datacenter-web.eastmoney.com/api/data/v1/get`。
- `reportName=RPT_F10_EH_FREEHOLDERS`：十大流通股东持股明细。
- `reportName=RPT_DMSK_HOLDERS`：十大股东持股明细。
- 中央汇金、证金公司按精确 `HOLDER_NAME` 过滤。
- 社保基金按 `HOLDER_TYPE="全国社保基金"` 或 `HOLDER_NEWTYPE="社保"` 过滤。

第一阶段不依赖 AkShare 包装层，避免包装字段变更影响可溯源字段映射。若后续加入 AkShare，只能作为备用源，仍需保留东方财富原始字段、来源链接和采集时间。

事件源第一阶段复用现有 `events` 体系和公开源采集能力。若没有可查事件，则返回空列表和来源状态，不生成虚构事件。

## 后端接口

新增接口前缀：`/api/v1/national-team`

### `GET /summary`

返回三类主体摘要：

- 主体 key 与名称。
- 最新报告期。
- 最新公告日。
- 当前命中持仓数。
- 新增、退出、增持、减持数量。
- 最新事件标题和时间。
- 数据源状态、采集时间。

### `GET /holdings`

查询参数：

- `entity`：`huijin`、`social_security`、`csf`，为空返回全部。
- `period`：报告期，格式 `YYYYMMDD` 或 `YYYY-MM-DD`。
- `page`、`size`：分页。

返回字段：

- 股票代码、股票名称。
- 主体 key、主体名称。
- 原始股东名称、股东类型。
- 股东排名、股份类型。
- 报告期、公告日。
- 持股数量、持股数量变化、变化比例、持股变动名称、流通市值。
- 持仓类型：十大股东或十大流通股东。
- 来源、来源链接、采集时间。

### `GET /events`

查询参数：

- `entity`：主体过滤。
- `date_from`、`date_to`：事件日期范围。

返回字段：

- 事件日期、主体、标题、摘要、关联股票、影响级别、来源、来源链接、采集时间。

### `POST /refresh`

手动刷新国家队数据。接口必须返回：

- 刷新的报告期列表。
- 抓取到的原始条数。
- 命中的国家队持仓条数。
- 写入或更新条数。
- 变动统计。
- 数据源状态。

## 数据库存储

新增表：

### `national_team_holdings`

保存每次最新快照后的持仓明细。唯一键建议为：

`entity_key + stock_code + shareholder_name + report_period + holding_type`

### `national_team_changes`

保存本次快照与上次同主体、同股票、同股东、同持仓类型记录之间的差异：

- `new`：首次记录。表示系统首次在快照中记录该主体、股票、股东和持仓类型组合，不等同于上市公司披露口径的“新进”。
- `increase`：增加。
- `decrease`：减少。
- `unchanged`：不变。
- `exit`：退出。

### `national_team_events`

保存可溯源事件。事件必须有来源，不允许保存生成式占位事件。

### `national_team_snapshots`

保存每次采集状态：

- 报告期。
- 原始条数。
- 命中条数。
- 来源。
- 成功或失败状态。
- 错误信息。
- 采集时间。

## 每日邮件

每日邮件新增“国家队动向”模块，位置建议放在涨停池摘要之后、推荐结果之前。

内容包括：

- 三类主体摘要。
- 今日新披露或新检测到的持仓变化。
- 最新可查事件。
- 简要分析。
- 来源与更新时间。

简要分析规则：

- 出现首次记录：提示“系统首次纳入快照，不等同于上市公司披露的新进”。
- 出现增持：提示“披露持股数量较上期增加”。
- 出现减持：提示“披露持股数量较上期减少”。
- 没有变化：提示“未发现新的公开披露变化”。
- 数据源失败：提示“数据源暂不可用，本次邮件不生成国家队判断”。

## 前端页面

新增菜单：`国家队动向`。页面基于现有静态前端风格实现，不引入新框架和构建工具。

布局：

- 顶部四个摘要卡片：全部命中、中央汇金、社保基金、证金公司。
- 主体筛选 tab：全部、中央汇金、社保基金、证金公司。
- 持仓披露表格。
- 最新事件列表。
- 右上角刷新按钮触发真实刷新接口。

表格列：

- 代码、名称、主体、股东名称、报告期、公告日、排名、持股数、变化、变化比例、流通市值、来源、采集时间。

状态处理：

- loading 状态。
- 空数据状态。
- 数据源失败状态。
- 不使用占位行。

响应式：

- 小屏幕下摘要卡片两列或单列。
- 表格使用现有横向滚动容器。
- 页面内容不能被侧边栏或顶部栏遮挡。

## 验收标准

- 本地后端启动后，`/api/v1/national-team/summary`、`/holdings`、`/events`、`/refresh` 可访问。
- 至少一个真实报告期可通过东方财富接口完成字段探测。
- 页面数据来自真实接口返回。
- 邮件 HTML 与纯文本均包含国家队动向模块。
- `frontend/` 修改同步到 `docs/`。
- 测试覆盖主体匹配、字段归一化、变动检测、API 基本返回、邮件模块渲染。
- 本地完成后端测试、前端静态检查和实际服务启动验证。
