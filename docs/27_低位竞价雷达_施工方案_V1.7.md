| V1.6 问题 | V1.7 决策 |

### 本轮核心修订（2026-10-10）

1. 竞价字段改为**按市场、交易阶段、来源逐字段取证**；分支 B 不再是默认预期，未经验证的普通五档不得入分。
2. T-1 低位池补齐**盘后实际调度、产物就绪与次晨校验**，不把插件 16 的独立 CLI 误认为已接入每日流水线。
3. `low_score` 只作为池先验参与一次合成，不再混入 `auction_score`；P0 预览期补最小结果标签与冻结基准，以使 Gate-STRATEGY 可执行。
4. 09:25 全池重排后，对**拟发布 Top N 每只股票**核验最终字段证据；全池确认数量不能代替逐票确认。

本轮不调整全市场旁路采样、通知拓扑等其他设计；原有 P0 假设仅在与上述四项不冲突时继续适用。

### 1.2 竞价字段能力分支（取证后决策）

免费公开接口（腾讯 `qt.gtimg.cn`、东财 `push2`）在 9:15–9:25 **能否稳定提供、以及如何映射**虚拟参考价、匹配量、未匹配量和普通五档，均未经实测。交易所竞价即时行情与连续竞价五档是不同口径；现有普通行情解析器的字段名称不能直接证明竞价语义。不得预设虚拟量必不可得，也不得预设字段 9–28 是普通五档：

```text
Phase 1 交易日采样（见 §4.1 数据源验证表）
  ├─ 实测确认某源稳定给出「虚拟参考价 + 虚拟匹配量 + 虚拟未匹配量」
  │     → 分支 A：完整因子（gap/金额/换手/相对量比/未匹配量/情绪值）
  ├─ 虚拟量不全，但确证竞价期另有独立、真实、持续更新的普通五档
  │     → 分支 B：有限因子 limited_v1
  │           仅用已验「虚拟参考价 + 昨收 + 五档挂单量 + 涨停/跌停价」
  └─ 没有可验证的虚拟量/普通五档，但虚拟参考价与昨收可验证
        → 分支 B-：最小因子 minimal_v1
             竞价子分只用 gap；低位分仅作池先验；榜单降级为「低位池高开排序」
```

- **P0 默认先按“字段未知、禁止正式入分”开发取证链路**，分支 A/B/B- 只能由 Phase 1 证据选择并冻结；虚拟参考价本身无法验证时，三分支均不得正式评分。
- `AuctionFieldCapability` 按 `source + exchange + market_phase + raw_field_index + semantic + unit + observed_at` 登记；同一字段在不同阶段可有不同含义，未验证字段为 `UNAVAILABLE`，不得沿用连续竞价解释。
- 分支 B 下，竞价金额/换手/量比**只有在源字段语义被实测确认后才加入有效权重集**；否则从权重集移除，不得填 0。
- 评分版本号：分支 B = `auction_v1_limited`，分支 A = `auction_v1_full`，分支 B- = `auction_v1_minimal`（见 §6）。

### 1.3 Gate 分级（数据、工程、策略三层）

**Gate-DATA（通过前只能开发回放/受限模式）：**
1. **G1 数据源核验**：至少两个完整交易日采样；确认腾讯主源字段索引、单位、时间语义和竞价期更新行为。
2. **G2 最终撮合核验**：取得 9:25 后可验证的开盘价/量；不能确认时标 `UNCONFIRMED`，不输出 `CONFIRMED`。

**Gate-ENG（通过前不得开启生产外发）：**
3. **G3 全链路恢复**：进程重启、源超时、DB 锁、快照写入中断可恢复；同日同策略版本/revision 只有一份逻辑最终信号。
4. **G4 推送可靠性**：Outbox 落库、各通道独立状态、幂等键、`SENDING` 崩溃恢复、失败重试与操作日志通过。
5. **G5 可观测与拓扑**：运行节点、真相源、跨机传输边界已写清；源时间/接收/评分/发布/SMTP 时点可追踪。

**Gate-STRATEGY（通过前只能称「观察榜单」）：**
6. **G6 预览期（积累样本）**：同时满足至少 10 个完整交易日与 100 个有效候选样本（阈值在预览期（积累样本）开始前冻结），全程不发送标的推荐。
7. **G7 策略验收**：P0 预览期逐日保存冻结榜单、未入榜候选、事前冻结的评价窗口/正例定义/同池基准、T 日固定窗口价格与缺失原因；据此计算 `Precision@N`、窗口收益、最大不利波动、可成交性代理指标、停发率和基准超额。没有真实排队成交证据时不得称“实际可成交率”。阈值在留出验证日之前冻结，不在代码中暗含，也不得用调参样本自身证明有效。

### 1.4 P0 与 P1 边界

- **P0a 取证/预览期运行**：数据字段核验、盘后产池接线与 T-1 低位池冻结、5 秒目标节奏采集、因子归一化、最终全池重排及逐票确认、原子快照、本地只读查询、三表持久化、最小结果标签采集、**全市场竞价快照旁路采样（§5.5）**；默认发「观察期预览」邮件（明确标注非推荐、策略验证中），不称标的推荐。
- **P0b 推荐升级外发**：Gate-DATA + Gate-ENG + Gate-STRATEGY 通过后，把「观察期预览」升级为「已确认观察榜单（推荐语义）」，开启单 dispatcher Outbox、通道级有界并发、故障告警。
- **P1 再做**：09:15 后竞价异动独立赛道、1–2 秒热点节奏、帧落库/时间线、共享持久层与 Render 实时展示、跨进程 SSE、9:30 后分时提醒、历史同刻基准自学习、多 worker 租约。
- **明确不做**：重构 13/16 插件、全市场逐笔重建、自动交易、Kafka/Redis/K8s、三源齐验。

## 2. 事实核验结论（已读代码，非"待核验"）

### 2.1 三个既有缺陷 —— 已确认存在

1. **竞价 pre_open 分支不触发（确认）**：`backend/plugins/smart_money_radar/scheduler.py:22` 读 `session.get("session", "non_trading_day")`，而上游 `backend/api/router_system.py::trading_session_status` 返回的是 `market_session`（约 60 行）。故 `name` 恒为 `non_trading_day`，竞价分支不执行。**施工直接修复**：兼容读取 `session.get("market_session", session.get("session", "non_trading_day"))`，并补回归测试。
2. **现有腾讯解析器不能直接作为竞价字段证据（确认）**：`smart_money_radar/sources/tencent_source.py::parse_tencent_orderbook` 将 `field[9–28]` 固定解释为普通五档，`quote_contract.parse_tencent_quotes` 已解析价、昨收、成交量/额、换手率、量比、涨跌停价和源时间；两者均按常规报价设计。**施工复用原报文提取与基础数值/时间校验，不直接合并两份“字段语义结论”**；`collector.py` 从同一原报文建立字段级取证记录，竞价期字段 9–28 仅在 Phase 1 证明其含义后映射。`quote_is_current` 只校验时效，不证明 `field[3]` 是虚拟参考价或 9:25 最终开盘价；`at_limit_price` 只校验价格相等，不证明可交易性。无需改动 13 插件的现有连续竞价业务。
3. **竞价采集对象错误（确认）**：13 插件 `service.py::load_watch_pool` 消费 `principal_capital` 候选池（≤40 只），非低位池。**新插件显式绑定 16 号低位池**，不改 13 业务。

> 以上三项是「代码结构事实」，可直接修；但**字段语义**（腾讯 field[6]/[37]/[38]/[49] 在竞价期到底代表什么）仍是实盘验证项，见 §4.1。

## 3. 端到端验收链：六里程碑（北京时间）

施工主线不是评分，而是把 **M0 产池 → M1 冻结 → M2 采集 → M3 确认 → M4 推送 → M5 绩效** 接成每天闭环、可验收的链。每个里程碑拆两列：**可计算阈值**（按方案参数可算，= 验收预期）与**实盘测量**（只能跑了填，= 验收结果，不作承诺）。

| 里程碑 | 时刻 | 可计算阈值（预期） | 实盘测量（结果） | 失败路径 |
|---|---|---|---|---|
| M0 盘后产池 | T-1 15:10 | 15:50 deadline；产出 `pool_hash/total_count` | 产池实际耗时、数据源成功率 | 告警 → 次日 STALE/SKIP |
| M1 门禁+冻结 | T 09:10→09:14:30 | 09:14:30 冻结截止；校验 `status/date/items/low_score/hash` | 门禁通过率、stale 率 | `PREPARE_FAILED / SKIPPED_NO_POOL / DEGRADED_STALE_POOL` |
| M2 竞价采集 | T 09:15–09:25 | 轮次预算 = `ceil(pool/batch/concurrency)*batch_timeout ≤ 5s`；single-flight | P95 采集耗时、覆盖率、源质量、跳轮数 | `DEGRADED` |
| M3 最终确认 | T 09:25 后 | fast 15s / confirm 60s；TopN 逐票确认；`PARTIAL ≥50% 且 ≥3` 仅发保留原位次的观察清单 | 9:25 后最终价量可得性、确认成功率、PARTIAL 率 | `UNCONFIRMED / PARTIAL_CONFIRMED` |
| M4 推送 | T 快照可查后 | `RETRY_MAX=2`；`SENDING_TIMEOUT=30s` | SMTP 受理延迟、邮件到达时间 | `RETRY_WAIT / FAILED_FINAL` |
| M5 绩效回填 | T 盘后 15:10 | 标签按 `snapshot_version+code+label_spec_version` 唯一 | 标签覆盖率、缺失率、`Precision@N`（预览期后） | 缺数据不补造 |

**每日 run 报告**：`auction_runs.milestones_json` 每天自动写六里程碑的 `started_at/finished_at/state/evidence/error`。验收口径就一条：**任一日六时戳齐全，缺一即可定位到环节**；不得只靠最终快照“看起来完成”掩盖中间断链。

**信号状态机**（每交易日/策略版本/revision 唯一）：

```text
INIT → PREWARMING → POOL_FROZEN → POLLING
                               ├─> PRELIMINARY → WAITING_FINAL
                               │       ├─> CONFIRMED → PUBLISHING → PUBLISHED
                               │       ├─> PARTIAL_CONFIRMED → PUBLISHING → PUBLISHED（仅观察清单）
                               │       ├─> UNCONFIRMED（超时/无最终证据）
                               │       └─> FAILED（数据严重不一致）
                               └─> DEGRADED / SKIPPED_NO_POOL / DEGRADED_STALE_POOL
```

- `CONFIRMED` 指「发布所需最终字段具有足够证据」，支持字段级证据 `confirmed_fields=["open_price"]`；总体信号可为 `PARTIAL`/字段级确认。
- 不得以 `datetime.now() >= 09:25` 把旧帧直接升级为 `CONFIRMED`。
- 通知状态只存于 Outbox，不把已 `PUBLISHED` 的信号 run 改回 `NOTIFYING`。
- 六里程碑与状态机映射：M0/M1 → `INIT→POOL_FROZEN`，M2 → `POLLING→PRELIMINARY`，M3 → `WAITING_FINAL→CONFIRMED/PARTIAL_CONFIRMED/UNCONFIRMED`，M4 → `PUBLISHING→PUBLISHED`，M5 盘后回填不改变当日 run 状态。`PUBLISHED` 不抹除快照中的 `confirmation_status` 与 `publication_kind`。

## 4. 数据采集契约：先准确，后快

### 4.1 统一数据结构（能力取证后分支，独立于供应商）

```python
class AuctionQuote:
    trade_date: str
    code: str
    name: str | None
    source: str                       # tencent | eastmoney | tdx
    source_timestamp: str | None      # 无源时间必须为 None，不造时间
    received_at: str                  # 北京时间带 +08:00
    market_phase: str                 # PRE_AUCTION | NON_CANCEL | FINAL | UNKNOWN
    indicative_price_yuan: float | None      # 虚拟参考价（分支 A/B 均需）
    prev_close_yuan: float | None
    float_shares: int | None
    price_limit_up_yuan: float | None
    price_limit_down_yuan: float | None
    # 分支 A：完整因子（仅实测确认可得时启用）
    indicative_match_shares: int | None
    indicative_unmatched_shares: int | None
    unmatched_side: str | None        # BUY|SELL|UNKNOWN
    final_open_price_yuan: float | None
    final_match_shares: int | None
    # 分支 B：有限因子（P0 默认，免费源可稳定提供）
    orderbook_bid_vol_total: float | None    # 五档买挂单量（近似，非未匹配量）
    orderbook_ask_vol_total: float | None
    # 审计字段（保留原始值，不默认是竞价匹配量）
    source_volume_raw: float | None
    source_amount_raw: float | None
    source_volume_unit: str | None    # lot | share | unknown
    field_capability_version: str     # 来源/交易所/时段/索引/语义/单位的取证版本

    quality_reasons: list[str]
    confirmed_fields: list[str]
```

**字段原则**：
- `indicative_*` 用于 9:15–9:25 预测；`final_*` 只能由最终撮合口径证据赋值。
- `orderbook_bid_vol_total` 是**五档挂单量的近似**，绝不写成 `unmatched_shares`（未匹配量）；二者不得混用。
- 上述 `orderbook_*` 只能从竞价期经对照验证的**真实普通五档**生成；字段 9–28 的存在、非零或更新本身都不足以通过。若原行情接口把买一/买二复用为虚拟匹配/未匹配量，应按其经验证的虚拟量语义解析，不能五档求和。
- 供应商原始值、单位、报文哈希保留用于审计；日志脱敏令牌。
- 源无法提供某字段 → 该因子从有效权重集移除，不以 0 伪造。
- `received_at` 不得写成 `source_timestamp`；无法度量真实传输延迟时标 `source_lag_unknown`。

## 6. 竞价因子、评分和风险口径

### 6.1 单位规则

内部标准单位：人民币元、股、百分比数值（2.5 代表 2.5%）。「手」按每手 100 股转换。

### 6.2 按能力启用的 A/B/B- 因子集（核心）

| 因子 | 分支 A（完整，待取证） | 分支 B（有限，待取证） |
|---|---|---|
| 竞价涨幅 `gap` | ✓（虚拟参考价 vs 昨收） | ✓ |
| 盘口压力 `orderbook_pressure` | 已验未匹配量与真实五档分开定义 | 仅真实普通五档经竞价期取证后启用 |
| 竞价涨停封单 `limit_up_seal` | 仅相应买量语义取证后启用 | 仅真实普通五档买量取证后启用 |
| 低位分 `low_score` | 不进入竞价子分；仅作池先验 | 不进入竞价子分；仅作池先验 |
| 竞价金额 `amount` | ✓ | 仅源字段语义实测正确才启用 |
| 竞价换手 `turnover` | ✓ | 同上 |
| 竞价相对量比 | ✓（历史 9:25 基准） | 同上；P0 无历史基准 → `null` |
| 未匹配量/情绪值 | ✓ | ✗（免费源大概率无） |

**分支 B-（受限观察态）**：未验证真实普通五档/虚拟量时，盘口压力、竞价涨停封单、挂单压力衰减全部失效；竞价活跃因子集仅 `{gap}`，`low_score` 只在外层合成一次。榜单语义降级为「低位池高开排序」，`strategy_version = auction_v1_minimal`，快照 `phase=DEGRADED_MINIMAL`，且默认不参与可交易榜；它的分数不可与 A/B 版本横比。

### 6.3 评分（缺失重归一化）

所有参与加权的值必须先经过版本化归一化，禁止将百分比、股数和 0–100 分直接相加：

```python
class FactorSpec:
    name: str
    normalization_version: str
    direction: str                 # positive | negative | band_pass
    required: bool
    weight: float
    normalize: Callable[[float, FactorContext], float | None]  # 输出 0..100

class FactorValue:
    raw_value: float | None
    normalized_value: float | None
    effective_weight: float
    missing_reason: str | None
    evidence_fields: list[str]
```

P0 冻结规则：

- `low_score`、`indicative_price_yuan`、`prev_close_yuan` 是低位赛道必选字段；必选缺失时不得靠权重重归一绕过。
- `weights` 只包含该 `strategy_version + factor_spec_version` 冻结的**已验证竞价因子**，不得包含 `low_score`；coverage 分母不得包含本分支明确不可用的因子。
- `gap` 默认使用区间型（`band_pass`）映射，不预设涨幅越大越好；预览期（积累样本）启动前先冻结可运行的初始阈值，若据预览期（积累样本）调参，则另留独立交易日验证，不在同一批样本上选择并验收。
- 盘口压力使用 `orderbook_imbalance`；规模特征如需入分，必须再除以流通股本或历史同刻基准。
- 快照必须带 `factor_spec_version`、`config_hash`、`code_commit`，任一变化都生成新策略修订标识。
- 分支 B-：竞价活跃因子集仅 `{gap}`，要求 `gap` 与池先验 `low_score` 均非空，竞价因子 coverage 必须为 1.00；榜单标 `DEGRADED_MINIMAL`，不称综合评分。`min_coverage=0.50` 在单因子情形没有筛选意义，禁止沿用。

```python
def weighted_auction_score(values, weights, *, min_coverage=0.70):
    valid = {k: v for k, v in values.items() if v is not None and k in weights}
    coverage = sum(weights[k] for k in valid) / sum(weights.values())
    if coverage < min_coverage:
        return None, coverage
    score = sum(valid[k] * weights[k] for k in valid) / sum(weights[k] for k in valid)
    return round(max(0, min(100, score)), 2), coverage
```

合成（权重为示例，需配置+复盘校准；`risk` 不再作为凭空加分的独立项）：

```python
base_score = W_LOW * low_score + W_AUCTION * auction_score   # low_score 只在这里出现一次；B 版权重须经预览期（积累样本）另行冻结
total_score = clamp(base_score - risk_penalty, 0, 100)
```

- 分支 B- 的 `auction_score` 仅由已验 `gap` 映射产生；`total_score` 仅作该版本内部低位池排序，不声称与 A/B 分数校准一致。
- 硬风险失败直接排除正式榜单（保留审计原因）；软风险 `risk_penalty` 0–100 扣分并存证。
- 同分按数据质量、冻结的次级指标、代码确定性排序；不以缺失字段填 0 制造随机波动。
- `strategy_version`：分支 B = `auction_v1_limited`；分支 A = `auction_v1_full`。

### 6.4 竞价涨停封单强度（V1.2 新增）

```python

    真实五档买一挂单量与虚拟未匹配量使用不同因子实现，不混称封单。"""
    # 复用 quote_contract.at_limit_price（分位精确匹配，不把接近涨停伪装成涨停）

        return None
    # 封单量规模 + 挂单量增速 合成 0-100；仅描述盘口强弱，不推断主力意图
```

- 封单强度只进入 `signal_strength`；可交易性由 `tradability` 独立判定。虚拟价在涨停且显示极强买盘、缺少可成交证据时，标 `UNTRADEABLE_OR_UNCERTAIN`，可进观察榜但不进可交易榜。
- 封单强度骤降 + 价格下移 → 转入「挂单压力衰减」风险（§6.5）。

### 6.5 挂单压力衰减（V1.2 替换「诱多撤单」）

```python
def orderbook_pressure_decay(frames, drop_pct=0.5) -> bool:
    """仅对经确认是真实普通五档的同源同阶段近 K 帧计算买量下降与价格下移。
    只描述「买盘挂单压力衰减 + 价格走弱」的可观测现象，不宣称撤单。"""
```

- **两个阶段都不宣称「撤单」**：9:15–9:20（可撤段）挂单量下降可能是撤单、被动成交或价格跳变；9:20–9:25（不可撤段）挂单变化来自新申报与价格变动导致的重新撮合。除非有申报级逐笔，否则只标 `events=["挂单压力衰减"]`。
- 该信号作为**软风险扣分** + 事件标注，不作为唯一硬过滤依据。

### 6.6 信号结果语义

每只股票输出：`low_score / auction_score / total_score / factor_coverage / quality / confirmed_fields / events / risk_flags / tradability / excluded_reason / strategy_version / factor_spec_version`。只展示可追溯的预测/最终价格与量；不得文案表述「机构买入」「主力建仓」等无可验证依据的结论。

### 7.2 原子发布 + 单 dispatcher Outbox

```text

(2) 短 DB 事务：upsert auction_runs(state=PENDING_PUBLISH)
                 + auction_candidates + auction_outbox(status=WAITING_PUBLISH)
(3) 提交成功后：复用 atomic_write_json（已 fsync+os.replace）写 reports/ 与 data_backend/
```

## 9. 推送链路：快实时且可恢复

### 9.1 消息类型与时机

| 类别 | 触发 | 原则 |
|---|---|---|
| 观察期预览 | 确认完成、快照已发布（预览期每天） | `【低位竞价雷达·观察】今日低位池竞价 Top N（非推荐）`；明确策略验证中、不构成投资建议 |
| 部分确认观察清单 | 原拟发 TopN 部分确认、达最低确认数且全池重排范围完整 | `【低位竞价雷达·部分确认观察】`；按原位次展示全部拟发股票，逐票列确认状态、未确认字段/原因及排序时点；不称正式 TopN、不递补 |
| 已确认观察榜单 | 确认完成、快照已发布且推荐 Gate 已通过 | `【低位竞价雷达】已确认观察 Top N`；含数据时间/质量/可交易性/免责 |
| 未确认告警 | 等待最终行情到期 | `【竞价数据未确认】今日不发送正式榜单`；列原因 |
| 采集故障 | 连续异常达阈值 | `【竞价雷达故障】`；不伪造标的 |
| 更正版本 | 已发正式榜单后有受验证更正 | 显示 revision/差异 |

### 9.2 单 dispatcher + 通道级有界并发

- 逻辑事件按 `(trade_date,phase,strategy_version,revision)` 生成稳定 `event_key`；每通道/收件人独立记录。
- 状态：`WAITING_PUBLISH→READY→SENDING→ACCEPTED`；失败 `RETRY_WAIT→READY` 或 `FAILED_FINAL`。
- dispatcher 一次只 claim 一个逻辑事件；同一事件的通道任务通过 `asyncio.gather(..., return_exceptions=True)` + Semaphore 有界并发，指数退避+抖动，`RETRY_MAX` 默认 2。
- `ACCEPTED` 表示远端服务**受理请求**，非投递到设备。
- 本地唯一键防本地重复入队；远端「恰好一次」不保证，尽可能用平台业务消息 ID。
- 多个收件人邮箱**各自独立执行**，不互相拖慢。
- 启动恢复：`status=SENDING` 且 `sending_started_at < now - sending_timeout` 的任务重置为 `READY`，记录 `recovered_after_crash`；依靠远端业务消息 ID 尽可能抑制重复。

### 9.3 邮件

- `send_email` 是同步 `smtplib` → 必须在 `asyncio.to_thread`/独立线程，禁止阻塞事件循环。
- 09:10 做 DNS/端口/认证健康检查（不误发测试消息）；TLS/认证保持。
- HTML 盘前预编译，9:25 只填数；展示 `asof`、确认状态、来源、因子覆盖度、风险说明。
- 区分 `SMTP_ACCEPTED` 与 `INBOX_DELIVERED`（后者需独立探针，不由发送函数推断）。

### 9.4 Webhook（P1 可选，本轮不实现）

- 本轮保持**原有邮件推送**（复用 `principal_capital.notifier.send_email`），不实现企业微信/钉钉/飞书/Telegram 机器人。
- P1 如需秒级即时通道，再按独立方案接入 Webhook 机器人；届时与邮件共用同一 Outbox 幂等键，并保持通道级超时/重试分离。

## 10. 性能、监控、恢复

### 10.1 端到端时间点（必须落日志/指标）

`source_timestamp → received_at → validated_at → scored_at → final_confirmed_at → published_at → smtp_accepted_at`

- `time.monotonic()` 记录单进程阶段耗时；绝对时间用 Asia/Shanghai；源时间不可信不计算伪造延迟。

### 10.2 第一版观测目标（交易日 P95 验收，非服务保证）

| 指标 | P95 目标 | 口径 |
|---|---|---|
| 增量评分 | ≤200ms | 有效行情收齐→评分完成 |
| 最终榜单发布 | ≤1s | 最终行情确认→快照可读 |
| 本地 `GET /latest` | ≤200ms | 请求→完整响应 |
| SMTP 受理 | ≤15s | 快照发布→SMTP 受理 |
| 快速确认尝试 | 尽力 09:25:15 前完成 | 及时性目标，不得压过真实性门禁 |
| 最终确认截止 | 默认 09:26:00 | 到期仍无可验证字段则 `UNCONFIRMED` |

- 区分「源到达慢」与「内部计算慢」；收件箱送达另测，不归本系统保证。

### 10.3 运行稳定性

- `launchd` 保活；监控 Mac 睡眠/唤醒、时钟漂移、关键时间错过。
- 运行手册必须明确防睡眠/电源策略、网络恢复和 NTP 偏差门禁；仅有 `launchd` 不等于不会错过竞价窗口。
- 启动读 DB/快照恢复当日 `auction_runs` 与 Outbox；9:25 后启动无法补最终数据 → 不回放旧预测当最终。
- 看门狗监控 `heartbeat_age / valid_quote_coverage / source_error_rate / last_confirmed_age / outbox_backlog / notification_accept_latency`。
- 连续失败发系统告警（冷却+去重），不生成虚假交易信号；全源失败/无池/非交易日可解释停发。
- 插件 13 与 28 不得在 09:15–09:25 对腾讯源各自无限速采集：P0 默认关闭 13 的旧竞价分支，或两者共享一个连接/全局 token bucket；决策项写入部署配置和验收日志。

|---|---|---|

| 语义 | 同一字段在竞价与连续竞价阶段含义不同 | 按市场/阶段映射，能力版本隔离，不跨阶段复用五档解释 |
| 语义 | 挂单量下降 + 价格下移 | `events=["挂单压力衰减"]`，**不写「撤单」** |
| 池 | 09:10 行情涨幅榜有数据 | 不把它当当日竞价强势清单；P0 冻结池成员不变 |
| 池 | 候选无 T-1 `low_score` | 不进低位赛道评分，不通过 coverage 重归一绕过 |

| 评分 | `auction_score` 包含 `low_score` 的配置 | 配置/测试拒绝；低位分只在总分合成出现一次 |
| 归一化 | 两票原始挂单股数差异大、不平衡率相同 | 归一化压力分一致，不因股本规模直接偏置 |
| 可交易性 | 虚拟价涨停且强封单、无可成交证据 | 信号强可进观察榜，`tradability=UNTRADEABLE_OR_UNCERTAIN`，不进可交易榜 |
| 最终性 | 09:24:55 预测价 ≠ 09:25 成交价 | 正式榜单只用确认后字段 |
| 最终性 | 09:25:15 前无可靠成交价，09:25:40 取得 | 允许在确认 deadline 内发布，记录快速目标未达成，不误标 `UNCONFIRMED` |
| 最终性 | 确认 deadline 到期仍无可靠成交价 | `UNCONFIRMED`，不冒充 `CONFIRMED` |
| 最终性 | 全池确认数量达标，但拟发 TopN 中一票缺最终价/量证据 | 正式 TopN 和标的通知停发，记录该票缺失字段；不能靠全局计数放行 |

| 部分确认 | 原拟发 TopN 少于 3 只，或全池重排范围不完整 | 不触发 `PARTIAL_CONFIRMED`；转 `UNCONFIRMED` 或明确覆盖范围的受限观察快照 |
| 排名 | 预测切线外股票在 09:25 跳入 TopN | 全冻结池重排后可入榜；非全池时快照显式标注未确认范围 |
| 回放 | 同一 run 触发 2 次 / daemon 重启 | 逻辑 run + outbox 唯一，无本地重复入队 |
| 一致性 | DB 成功、快照替换前崩溃 | 重启重建或标失败，不丢 outbox |

| API | 生产未配 `RADAR_AUCTION_TRIGGER_TOKEN` | `/trigger` 不注册或拒绝访问，不降级为无认证 |
| 推送 | SMTP 成功 / 失败 | 各自独立状态与重试 |

| 系统 | iMac 睡眠错过竞价 | 健康告警，不造最终结果 |

| 预览期（积累样本） | 有 10 天/100 票但结果标签缺失或调参与验收复用同一批交易日 | Gate-STRATEGY 不通过，先补标签或独立验证日 |

## 14. 开发完成判定（Definition of Done）

**主线：端到端验收链（M0–M5）每天闭环、可定位、可验收。**

1. 任一交易日，`auction_runs.milestones_json` 六里程碑的 `started_at/finished_at/state/evidence/error` 齐全；缺一即可定位到环节，不以最终快照“看起来完成”掩盖断链。
2. 每个里程碑的「可计算阈值」全部满足，「实盘测量值」已如实记录且未当作收益承诺。
3. §2.1 三个缺陷有复现、修复与回归测试；竞价字段能力按市场/时段冻结为 A/B/B- 或无法排序，不默认借用普通五档。
4. P0 只冻结有效 T-1 低位池（仅沪深主板 60/000/001/002/003）；`low_score` 只在外层出现一次；必选因子不能被 coverage 重归一绕过。
5. 09:25 默认全冻结池重排，拟发 TopN 逐票确认才发布 `CONFIRMED`；`PARTIAL_CONFIRMED` 仅发保留原名单/位次和未确认原因的观察清单，不递补、不压缩名次、不称正式 TopN。
6. 本地单节点是 P0 真相源；GET 纯本地快照/DB 无外部行情调用；`/trigger` 默认禁用且不允许空 token 降级。
7. 邮件使用单 dispatcher + 通道级有界并发；状态独立，幂等键和 `SENDING` 崩溃恢复已验证。
8. 日志能解释每次信号从行情→快照→SMTP 的延迟，并带配置/因子/代码版本。
9. 具备启停、故障恢复、非交易日、睡眠错过时段的运维说明；全市场旁路采样按日落盘且失败不阻塞主链路。
10. 不自动交易、不承诺收益；「可计算阈值」与「实盘测量」在验收报告里分列，不把理论值当收益。

> 解析函数必须 `len(fields)` 越界保护并返回 `None`，不抛异常。`field[3]` 是否为竞价虚拟参考价、`field[9–28]` 是否为真实普通五档、9:25 后何时变为最终撮合价量，均以 Phase 1 沪深主板分时段实测为准；普通解析器命名只作定位，不是语义证据。
