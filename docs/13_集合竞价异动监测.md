# 13 集合竞价异动监测 — 产品开发技术方案

## 1. 目标与定位

覆盖现有 12 个方案完全空白的短线核心场景：集合竞价阶段（早盘 09:15–09:25、尾盘 14:57–15:00）的抢筹 / 诱多识别。竞价撮合期 pytdx 五档反映虚拟开盘价与匹配量，数据准、时效强，是打板与低吸的第一手信号。

优先级：**P0（本地 pytdx 类，接近 L2，短线价值最高）**。本地雷达采集端现成，改动集中在调度时窗与新增指标。

## 2. 产品方案

### 2.1 页面模块
- 竞价异动榜：观察池内按竞价高开幅度 / 竞价金额 / 匹配量强度排序。
- 个股竞价时间线：09:15–09:25 每次采样的虚拟开盘价、匹配量、未匹配挂单量曲线。
- 事件提示：高开抢筹、竞价金额突放、疑似撤单诱多、昨日涨停今日竞价强度。

### 2.2 输出口径
- 竞价高开幅度 = (竞价虚拟开盘价 - 昨收) / 昨收。
- 竞价匹配金额 = 虚拟开盘价 × 匹配量。
- 匹配量增速 = 最近 K 次采样匹配量斜率（正 = 持续承接）。
- 撤单诱多信号：09:15–09:20（可撤单段）挂单量高，09:20–09:25（不可撤段）挂单量骤减且开盘价下移 → 疑似诱多撤单。
- 昨日涨停今日竞价强度：昨日涨停股今日竞价高开幅度分布（与 01 情绪周期联动）。

## 3. 技术方案

### 3.1 数据源
- `backend/plugins/smart_money_radar/sources/tdx_source.py::TdxPool.fetch_stock` 返回的 `quote`（含五档 bid/ask、虚拟开盘 `price`、`last_close`、`servertime`）。
- 竞价期沿用现有采集端，**不新增连接**。

### 3.2 调度切入（关键）
- 当前 `scheduler.py` 的 `pre_open` 分支仅 `sleep 30`（`scheduler.py:16,58`），竞价窗口空转。
- 改造：在 `pre_open` 且时间落在 **09:15–09:25** 时，启用竞价采集轮询（间隔可配 `auction_poll_interval_s`，默认 5s），其余 pre_open 时段维持 sleep 预热。
- 尾盘竞价 14:57–15:00 在 `trading`/`closed` 边界追加采样。

### 3.3 算法
- 在 `smart_money_radar/` 新增 `auction.py`（纯函数）：
  - `auction_gap(quote)`：竞价高开幅度；
  - `auction_amount(quote)`：竞价匹配金额；
  - `match_vol_slope(series)`：匹配量增速；
  - `withdraw_lure(series)`：撤单诱多启发式判定。
- 事件阈值进 config（`RADAR_*` env 覆盖）。

### 3.4 数据陷阱
- 竞价撮合期 vol/amount 口径与连续竞价不同，承接 `indicators._valid_bars` 的集合竞价过滤经验（`indicators.py:71`），异常值（vol≈0）跳过。
- 09:25:00 撮合完成瞬间数据跳变，以 09:24:5x 最后一帧为准。

## 4. 数据存储方案

- 竞价采样帧只存本地内存滑动窗口（复用 `RadarStore`，可加轻量 `auction_frames` 缓冲，收盘 reset）。
- 触发事件写 `data/auction_events_{date}.json`。
- 聚合结果写 `reports/auction_latest.json`。

## 5. 数据读取方案

- `GET /api/v1/smart-money-radar/auction/latest`：读 JSON 快照。
- `GET /api/v1/smart-money-radar/auction/{code}`：本地读内存竞价采样序列。
- 竞价页面轮询刷新，复用前端 `apiFetch` 模式。

## 6. 与现有系统集成

- **扩展** `backend/plugins/smart_money_radar/`：新增 `auction.py`，改造 `scheduler.py` 竞价时窗，`service.py`/`router.py` 加事件判定与端点。不新开插件、不新增采集端。
- 竞价事件可并入雷达邮件（《本地雷达》tag），复用 `should_notify` 冷却去重。
- 昨日涨停今日竞价强度与 **01 情绪周期** 的涨停池联动，作情绪修复 / 退潮的先行信号。

## 7. 测试与验收

- 指标边界：昨收=0 防除零；全空挂单不触发；高开幅度符号正确。
- 撤单诱多判定：09:15–09:20 挂单高 + 09:20 后骤减 + 开盘价下移 → 触发；正常放量承接不触发。
- 时窗测试：09:15–09:25 启用采集、09:26 后停止；尾盘 14:57–15:00 追加采样。
- 验收：交易日竞价窗口稳定产出观察池竞价榜，事件可解释、无重复刷屏。

## 8. 上线与运维

- 本地常驻 `--run-radar-daemon`，launchd 保活；竞价采集随主循环启停。
- 阈值 / 时窗 / 采样间隔用 `RADAR_*` env 覆盖。
- 竞价窗口仅每交易日两段，资源占用极低。

## 9. 风险与限制

- pytdx 竞价期刷新频率有限，撤单诱多为启发式近似，非交易所精确委托明细。
- 只有五档，看不到完整未匹配委托队列；撤单信号是未匹配挂单量变化的推断。
- 依赖本地开机 + 国内 IP + daemon 运行（本地 pytdx 类通用约束）。

## 10. 里程碑

1. M1：`auction.py` 竞价指标纯函数 + 单测。
2. M2：`scheduler.py` 竞价时窗采集 + 事件判定 + 内存缓冲。
3. M3：页面 + 邮件提示 + 与 01 情绪周期联动。
