# 17 四维共振 K 线副图与实时提醒 — 产品开发技术方案

## 1. 目标与定位

把方案 15 的四维共振信号从"盘后榜单"升级为"涨前主动提醒 + K 线副图"。核心目标是：**主力开始建仓但价格还未启动的那个窗口内，系统已经发出通知**。事后的信号没有交易价值。

优先级：**P1**。依赖方案 15 稳定运行 20 个交易日后实施。

与方案 15 的区别：
- 方案 15：盘后日频扫描，看榜单，被动查阅
- 方案 17：盘中 5 分钟主动推送 + K 线副图，主动提醒，涨前触发

---

## 2. 核心设计决策（从 grill 对齐结论）

### 2.1 "涨前提醒"的数据颗粒度现实

现有技术栈能做到两种模式，颗粒度不同：

| 模式 | D1 资金 | D2 价格 | D4 量能 | 覆盖范围 | 提前性 |
|------|---------|---------|---------|----------|--------|
| 盘后全市场（方案 15 现状） | 日频 | 日线收盘价 | 日线量比 | 主板 3000+ 只 | 次日参考，非实时 |
| 盘中全市场（方案 17 A 阶段） | 5 分钟东财 | **当日实时价** | **盘中累计量** | 主板 3000+ 只 | 主力建仓时触发 |
| 盘中观察池精细（方案 17 B 阶段） | 5 分钟东财 | pytdx 实时价 | pytdx 逐笔量 | 观察池 40 只 | 最精细，秒级感知 |

**真正"涨前"的关键**：D2 必须用当日实时价重算，而不是昨日收盘价。主力开始净买入时价格可能还没动（D1 已经拉高），等日线 D2 响应已经晚了一天。

### 2.2 D2/D4 盘中实时化改造

```python
# 现有方案15 D2（日线，盘中不变）
def d2_score(closes: list, highs: list) -> Optional[float]:
    # closes[-1] 是昨日收盘价，盘中不更新

# 方案17 D2（实时价替换最后一个收盘价）
def d2_score_intraday(closes: list, highs: list,
                      realtime_price: float) -> Optional[float]:
    """
    把 realtime_price 替换 closes[-1] 后重算动量分。
    realtime_price 来自东财资金流 API 的 price 字段（5分钟刷新）。
    5日收益 = (realtime_price - closes[-6]) / closes[-6]
    20日收益 = (realtime_price - closes[-21]) / closes[-21]
    距高点 = (max(highs[-20:]) - realtime_price) / max(highs[-20:])
    """

# D4 盘中量比（用累计量替代日线量）
def d4_score_intraday(vols: list, intraday_vol: float,
                      prev_avg_vol: float) -> Tuple[float, float]:
    """
    intraday_vol: 今日到目前累计成交量（东财 API 的 vol 字段）
    prev_avg_vol: 过去5日日均量
    日内量比 = intraday_vol / (prev_avg_vol * 当前时间占全天比例)
    """
```

### 2.3 推送必须在盘中触发，不能等盘后

盘后汇总推送等于"已经涨完再告诉你"，无交易价值。

推送时机：`run_resonance_once`（盘中 5 分钟循环）发现新 RED 信号（该 code 在过去 30 分钟内未推送过）→ 立即推送，不等收盘。

冷却机制：同一只票 30 分钟内不重复推送（复用 `should_notify` 机制），防止 5 分钟循环刷屏。

### 2.4 路径 A → 路径 B 升级提醒机制

路径 A（个股折线图）上线后，当 `resonance_snapshot` 表积累满 **20 个交易日**，API 响应里自动加入升级提示：

```python
# service.py run_resonance_once 末尾
days_count = db_query(
    "SELECT COUNT(DISTINCT date) AS c FROM resonance_snapshot"
).iloc[0]["c"]
if days_count >= 20:
    payload["upgrade_hint"] = (
        "resonance_snapshot 已积累 20 个交易日，"
        "路径 B（ECharts K线副图）方案可以实施，请启动方案 17 路径B施工。"
    )
    payload["trading_days_accumulated"] = int(days_count)
```

这条 hint 会出现在 `/api/v1/resonance/latest` 的响应里，前端检测到后在 Dashboard 顶部显示一条蓝色 banner 提醒。

## 3. 分阶段实施

### 路径 A：个股折线图（M3 里程碑，2-3 天，先上线）

**目标**：在个股详情页加共振分历史折线，积累数据 + 校准阈值，为路径 B 打基础。

**改动**：
- 后端：`/api/v1/resonance/{code}` 已有，返回历史 `date/resonance_score/signal/d1~d4`，无需改动
- 前端：在个股详情页下方加一个折线图区域，横轴日期，纵轴 0-100，D1/D2/D3/D4 四条折线 + 总共振分一条加粗线，信号灯用背景色标注（RED=淡红/GREEN=淡绿）
- 实现：原生 JS + SVG，不引入新依赖，约 150 行

**不做**：实时刷新，D2/D4 日内化，推送。这些留路径 B。

### 路径 B：ECharts K线副图 + 盘中实时推送（独立方案，1-2 周）

触发条件：路径 A 上线 + `resonance_snapshot` 积累 20 个交易日 + 阈值校准完成。

**四个子任务**：

#### B1：D2/D4 盘中实时化

```
修改文件：backend/plugins/resonance/indicators.py
新增：d2_score_intraday(closes, highs, realtime_price) -> Optional[float]
新增：d4_score_intraday(vols, intraday_vol, prev_avg_vol) -> Tuple[float, float]
修改：service.py 的 evaluate_resonance 在盘中时段调用 intraday 版本
数据来源：fetch_market_fund_flow_resilient 返回的 price 和 vol 字段（已有）
```

#### B2：盘中 5 分钟循环接入

```
修改文件：backend/main.py（scheduler 接入）
逻辑：trading_session == "trading" 时，每 5 分钟触发 run_resonance_once
复用：principal-capital-scan 的冗余触发+自循环机制（已有）
```

#### B3：盘中实时推送

```
新增文件：backend/plugins/resonance/notifier.py
函数：notify_new_signals(new_red: list, new_green: list, now: datetime)
推送渠道：复用 backend/plugins/principal_capital/notifier.py::send_email
冷却：复用 should_notify（30分钟冷却，同一 code 不重复）
触发时机：run_resonance_once 跑完后对比上一轮快照，找出新增 RED/GREEN 立即推
```

#### B4：ECharts K 线副图

```
引入：ECharts 5.x（CDN，约 800KB，Apache 开源）
替换：当前个股页的手写折线图（路径 A 的成果）
副图布局：
  主图：K 线（收盘/开盘/最高/最低）
  副图1：四维共振分（0-100，柱状，RED/GREEN/YELLOW 三色）
  副图2（可折叠）：D1/D2/D3/D4 四条折线
信号标记：RED 在 K 线柱下方打上三角，GREEN 打下三角（类通达信副图效果）
数据来源：/api/v1/resonance/{code} 历史时序 + 行情 API 当日 K 线
```

ALTER TABLE resonance_snapshot ADD COLUMN notified INTEGER DEFAULT 0;

## 6. 测试与验收

路径 A：
- 个股页折线图渲染 10+ 个交易日数据不报错
- 空数据（新上线第一天）显示"暂无历史数据"而非崩溃

路径 B（D2/D4 实时化）：
- `d2_score_intraday(closes, highs, realtime_price=realtime)` 与 `d2_score(closes+[realtime], highs)` 数值一致
- 盘前（09:00）realtime_price 为 None 时降级到日线 D2，不抛异常
- 盘中推送：新 RED 信号 30 分钟内只推一次，不刷屏

- K 线和共振分副图 X 轴日期对齐
- RED 三角打在正确的 K 线柱下方
- 无信号日（YELLOW）不打标记

## 7. 风险与限制

- D2 实时价用东财 API 的 `price` 字段，该字段在集合竞价期间是虚拟开盘价，09:15-09:25 期间 D2 分不准——这个时段用日线 D2 降级处理。
- 全市场 3000+ 只 5 分钟重算一遍 D2/D4，比盘后版慢（增加了实时价替换逻辑），但 K 线只有路径 B 才拉，路径 A 不影响性能。
- ECharts 是前端新依赖，CDN 加载失败时需要本地 fallback 或优雅降级（显示路径 A 的 SVG 折线）。
- 信号只是辅助参考，不构成投资建议；页面和邮件必须显示此声明。

## 8. 里程碑

- M1（路径A）：个股页折线图上线，`resonance_snapshot` 开始积累历史数据，升级提醒机制注入 API。
