## 2. 总体架构与数据流

### 2.1 扫描侧（替换 F2/F3 的承载）

```
每轮（GH Actions 全天每 5min；本地 daemon 心跳顺带跑，双跑幂等）：
 1. bulk 单请求 ssl_bkzj_ssggzj(num=8000, sort=r0_net, asc=0)      ← 全市场 6430 行/0.8s
 2. 粗筛圈定（config 阈值，含保底重圈 §4.2）：
      买侧 ratioamount*100 ≥ HUB_COARSE_BUY(40)     → ~35 只
      卖侧 ratioamount*100 ≤ -HUB_COARSE_SELL(24)   → ~450 只（全量精算，P3 实测头部截断漏检 83%）
 3. 逐票精算 ssi_ssfx_flzjtj（并发 20，实测 449 只 2.3s）→ 得精确 main_net/main_ratio（与原口径同源同式）
 4. 喂既有 filter_buy_candidates/filter_sell_candidates（阈值 50/30 不变）→ buy/sell 候选
 5. 邮件/去重/报告沿用现逻辑（买入邮件保持降级；新增 11:30/15:00 买入摘要，见 §7）
```

### 2.2 特征侧（池内票，替代"自算差分"）

```
池内 ≤40 只：东财 fflow daykline（klt=5，每票 1 请求，≤40 请求/轮，失败重试+当日缓存）
  → 滚动30min主力净流入 / 连续净流入窗口 acc_win / 5min增量占比
  → 无基线、无跨源污染、冷启动可重建（官方口径）
```

### 2.3 池侧（雷达持续跟踪，替代 F4 换血）

```
principal_capital_latest.json 双结构（向后兼容）：
  buy_triggered / sell_triggered         ← 本轮 fresh（现字段，语义不变）
  buy_triggered_today / sell_triggered_today ← 全天累计（新增）
  行内 fresh: true/false                 ← 新增标记
radar load_watch_pool 池策略（pool_max=40）：
  1) fresh 保证席 ≤20；2) 余额按 |当日累计净流入| 排序；3) min_dwell=30min 驻留
```

## 4. 纯函数规格（全部单测覆盖）

### 4.1 `parse_bulk_rows(payload) -> list[dict]`（sina_market 追加）
输入 ssggzj JSON 列表；输出与现 `_COLUMNS` 同构：code/name/price/change_pct/total_amount(=amount)/main_net_inflow(占位=None)/main_inflow_ratio(占位=None)/super_net(=r0_net)/big_net(占位)/mid_net(占位)/small_net(=r3_net)/`ratioamount`/`r0_ratio`/source="sina_bulk"。防除零/空值同现范式。

### 4.2 `coarse_select(rows, cfg) -> (buy_codes, sell_codes, coarse_warning)`
- 买侧：主板 AND ratioamount*100 ≥ cfg.coarse_buy（默认 40）；卖侧：主板 AND ratioamount*100 ≤ -cfg.coarse_sell（默认 24）。
- 阈值留余量 = 圈定不漏的兜底（实测 40/24 时圈定外越界 0）。
- **保底重圈（grill P2，硬止损非软提示）**：任一侧圈定集 ≤ `coarse_min_candidates`（默认 5）→ 该侧阈值自动 ×0.7（`coarse_fallback_ratio`）重圈一次，并置 `coarse_warning=true`；精算后 `refined_count / scanned < coarse_warning_ratio`（默认 0.001）同样置位写快照，前端黄条展示。

### 4.3 `refine_candidates(codes, fetcher) -> DataFrame`
对**买+卖全部圈定集**逐票调 `fetch_single_stock_fund_flow_sina`（并发 Semaphore(20)，实测 449 只 2.3s），产出与现全量扫描**完全同构**的 DataFrame → 直接喂既有 filter 函数。**禁止头部截断**：grill P3 实测卖侧头部 150 漏检 83%（超大单头部 ≠ 主力占比头部）。失败 code 单独记录（§6 `refine_partial_failure`）。

### 4.4 `merge_daily_cumulative(prev_today: dict, fresh_rows: list, now) -> dict`
- `_today` 累计：code → 当日最新行 + `fresh` 标记；跨轮并集（幂等，双跑无冲突）。
- 收盘/跨日重置（沿用 BEIJING_TZ）。
- **grill P5**：`now` 参数强制 `tzinfo is not None`（断言拒绝 naive datetime，防 GH Actions UTC 环境下误触重置）；workflow 加 `TZ=Asia/Shanghai` env 双保险。

### 4.5 `minute_features(bars: list, windows=[6,12]) -> dict`
输入 fflow klt=5 bars（f52 主力净额）；输出 `roll_net_30m`（6 根 5min 累加）、`acc_win`（连续净流入窗口数）、`inc_ratio_5m`（末根/末根对应 amount）。空序列/不足窗口 → 全 None + `warming=True`（不伪造）。

### 4.6 `dwell_persist(pool, path) -> None`（grill P4：驻留时间表持久化）
- 独立文件 `reports/data_backend/radar_pool_dwell.json`：`{code: {"entered_at": ISO}}`，本地与 GH Actions 双端同写；`commit_screening_data.sh` 整目录复制 reports/ 已覆盖提交，`restore_screening_data.sh` 恢复清单加一行拉回。
- `load_watch_pool` 优先读该表计算 min_dwell；文件缺失/损坏 → 内存表降级（本地 daemon 无影响，GH Actions 首轮驻留从当轮计时）。
