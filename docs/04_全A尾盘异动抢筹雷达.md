# 04 全 A 尾盘异动 / 抢筹雷达 — 产品开发技术方案

## 1. 目标与定位

每个交易日 14:30 / 14:45 / 14:55 输出全市场“温和放量、资金净流入、尚未涨停”的股票，抓“启动前”而不是“已经涨停”。与 `overnight_arbitrage` 区别：覆盖全 A、盘中 5 分钟更新、强调尾盘加速。

优先级：P1。复用现有主力资金 5 分钟循环，性价比高。

## 2. 产品方案

### 2.1 页面模块
- 尾盘抢筹榜：涨幅 3%–8%、换手活跃、量比放大、主力净流入、尾盘 30 分钟涨幅加速、未涨停。
- 个股时间线：当日 5 分钟快照序列，标注 14:20 / 14:50 两个观察点。
- 观察池：Top 40 自动喂给本地 `smart_money_radar` 做二次确认。

### 2.2 输出口径
- 尾盘强度 = 14:50 快照涨幅 - 14:20 快照涨幅。
- 尾盘资金强度 = 尾盘 30 分钟主力净流入 / 成交额。
- 尾盘分 = 涨幅分 + 量能分 + 资金分 + 加速分。

## 3. 技术方案

### 3.1 数据源
- 主力资金循环：`principal_capital` 每 5 分钟全市场扫描结果。
- 行情快照：`eastmoney_quote` / `data_backend.snapshots`。
- 本地二次确认：`smart_money_radar` 五档 + 逐笔 + VWAP。

### 3.2 算法
- 在每次 5 分钟扫描时，多存一张 `change_pct / amount / 量比 / 主力净流入` 快照。
- 尾盘加速用快照差值计算，无需额外分钟 K，覆盖率、速度和成本最优。
- 过滤复用 `principal_capital.service` 的 `_is_main_board / _is_excluded_market / _is_star_market / _is_st_name`。

### 3.3 调度
- 盘中 14:20–15:00 每 5 分钟一轮。
- GitHub Actions 定时触发不可靠，沿用 principal-capital-scan 的冗余触发 + 自循环模式。

## 4. 数据存储方案

```sql
CREATE TABLE intraday_quote_snapshot (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  date TEXT NOT NULL,
  hhmm TEXT NOT NULL,
  code TEXT NOT NULL,
  name TEXT,
  change_pct REAL,
  amount REAL,
  volume_ratio REAL,
  turnover REAL,
  main_inflow REAL,
  main_inflow_ratio REAL
);
CREATE INDEX idx_iq ON intraday_quote_snapshot(date, hhmm);
CREATE INDEX idx_iq_code_date ON intraday_quote_snapshot(code, date);
```

聚合快照：`reports/tail_raid_latest.json` + `reports/data_backend/tail_raid_latest.json`。

## 5. 数据读取方案

- `GET /api/v1/tail-raid/latest`：读 JSON 快照。
- `GET /api/v1/tail-raid/stock/{code}?date=`：走 `idx_iq_code_date` 读当天时间线。
- 页面显示源与滞后：缓存降级时标注“N 分钟前数据”。

## 6. 与现有系统集成

- 新增 `backend/plugins/tail_raid/`，读取 `principal_capital` 最新报告并叠加行情快照。
- `main.py` 注入 router + `--run-tail-raid-once`。
- 结果与 `smart_money_radar` 共享观察池，避免重复采集。

## 7. 测试与验收

- 快照差值测试：14:20 / 14:50 涨幅差计算正确。
- 过滤测试：300/301/688/ST 被剔除。
- 验收：交易日 14:30 后输出 20–50 只，且无已涨停票。

## 8. 上线与运维

- 并入 principal-capital-scan 自循环，或独立 cron 冗余触发。
- 生成物只提交 `data-snapshots` 分支。

## 9. 风险与限制

- 尾盘抢筹不等于次日溢价，需与 03 方案的概率校准联动。
- 美国 IP 直连东财不稳，依赖新浪兜底与快照分支。

## 10. 里程碑

1. M1：5 分钟快照落库。
2. M2：尾盘加速 + 尾盘分计算。
3. M3：页面 + 本地雷达观察池联动。
