# 03 T+1 溢价样本库与隔夜套利概率校准 — 产品开发技术方案

## 1. 目标与定位

现有 `overnight_arbitrage` 只输出 BUY/WATCH 信号，缺少“历史上相似样本赚不赚钱”的概率表达。本方案把信号升级为：
- 次日溢价概率、期望收益、正收益概率、最大回撤中位数；
- 策略胜率、盈亏比、期望值、样本数；
- 阈值调整后的即时回测结果。

优先级：P1。把“参考性”做实，不报样本内成绩。

## 2. 产品方案

### 2.1 页面模块
- 信号卡片：在现有隔夜套利信号上叠加概率与期望收益。
- 策略绩效面板：胜率、盈亏比、期望值、样本数、近 N 日表现。
- 阈值敏感性：拖动阈值即时显示样本外回测结果。

### 2.2 输出口径
- 标签：买入后 T+1 开盘 / 最高 / 收盘 / 最低收益。
- 特征：封板时间、炸板次数、连板数、成交额、换手率、量比、涨跌幅、流通市值、分钟强度、板块热度。

## 3. 技术方案

### 3.1 样本构造
- 复用 `backend/services/backtest.py` 的无前视逻辑，只用触发日及之前数据。
- 收益用触发日之后 T+1 价格计算，禁止未来函数。

### 3.2 模型
- 第一版：历史分位 / 朴素贝叶斯校准，零新依赖、可解释。
- 进阶版：本地用 `lightgbm` 做概率输出 + SHAP 归因，不增加 Render 依赖。
- 验证：滚动切分（walk-forward），报告样本外胜率。

### 3.3 调度
- 盘后增量写样本；本地/盘后跑校准模型。
- 页面读预计算 calibration JSON。

## 4. 数据存储方案

```sql
CREATE TABLE oa_sample (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  date TEXT NOT NULL,
  code TEXT NOT NULL,
  features_json TEXT NOT NULL,
  label_t1_open REAL,
  label_t1_high REAL,
  label_t1_close REAL,
  label_t1_low REAL,
  score_bucket TEXT
);
CREATE INDEX idx_oa_sample_date ON oa_sample(date);
CREATE INDEX idx_oa_sample_code ON oa_sample(code);

CREATE TABLE oa_calibration (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  date TEXT NOT NULL,
  model_version TEXT,
  metrics_json TEXT NOT NULL
);
```

- 大规模回测样本本地用 Parquet：`data/research/oa_samples.parquet`。
- 页面快照：`reports/oa_calibration_latest.json`。

## 5. 数据读取方案

- `GET /api/v1/overnight-arbitrage/calibration/latest`：读预计算 JSON，秒开。
- `GET /api/v1/overnight-arbitrage/calibration/samples?score_bucket=`：按需查明细。
- 前端信号卡片从 latest 信号 + calibration 概率合并展示。

## 6. 与现有系统集成

- 在 `backend/plugins/overnight_arbitrage/` 内新增 `calibration.py` 与 `router` 扩展，避免新开插件。
- 复用 `overnight_arbitrage` 的 `_decision_item` 特征与 `backtest.py` 收益口径。

## 7. 测试与验收

- 无前视测试：删除未来数据后样本结果不变。
- 校准测试：样本外 vs 样本内报告，样本外作为验收口径。
- 验收：样本数 > 200 时输出概率，样本不足显示“样本偏少”。

## 8. 上线与运维

- 盘后增量写样本，避免影响 14:43 决策链路。
- 模型版本化，回滚时保留上一版 metrics。

## 9. 风险与限制

- 历史统计非未来承诺；市场风格切换会导致校准失效。
- 样本不足或幸存者偏差需显式提示。

## 10. 里程碑

1. M1：样本落库 + 标签生成。
2. M2：朴素贝叶斯校准 + 面板。
3. M3：lightgbm 进阶（本地可选）。
